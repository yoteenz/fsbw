## Response style

- Complete sentences; high-quality prose — not telegraphic bullet chains in summaries  
- Teach alongside implementation — diagrams, tables, spatial analogies  
- Distinguish **proven** (device-confirmed) vs **inferred** (code-only)  
- State "not documented in capsule" when uncertain — do not guess canon  

## Prompt structure

| Role | Block label |
|------|-------------|
| Implementation | `COMPOSER SPRINT` |
| Review | `TERRA REVIEW` / architecture review |
| External AI onboarding | Three capsules + ONBOARDING_REPORT |

- One testing URL per code block  
- User-facing copy-paste prompts in ` ```text ` fences  

## Review & approval

- Visual mockups when founder prefers visual review first  
- Admin pages: **named page + named sections** before changes (Frontal Slayer Admin Alignment Protocol)  
- External AI: complete onboarding report → **wait for founder approval**  

## Critique philosophy

Direct, forensic, constructive. Fix root cause. No "modernization" without authorization.

## Teaching philosophy

Explain *why* decisions were made so the next collaborator inherits judgment, not just instructions.
