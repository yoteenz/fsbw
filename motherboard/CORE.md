# Core Context — Build-a-Wig / Frontal Slayer

Canonical reference for stack, design, and main flows. Keep this updated when the project’s **persistent** design or architecture changes.

---

## Stack & repo

- **Frontend:** React 19, TypeScript, Vite 5, React Router 6, Tailwind CSS.
- **Backend / Auth / DB:** Supabase (Auth, profiles, orders, cart, wishlist, key/value **app_config** for site-wide JSON such as the admin special-offer card, **`site_analytics_events`** for marketing/social click analytics ingested via `POST /api/analytics/event`). Vercel serverless API routes under `api/`. Full table definitions, RLS, and `auth.users` → `profiles` trigger: run `supabase/migrations/20260325120000_full_app_sync.sql` in the Supabase SQL Editor when setting up or repairing sync. Marketing/admin JSON: also run `supabase/migrations/20260325140000_app_config_marketing.sql` for the `app_config` table. Analytics: run `supabase/migrations/20260330180000_site_analytics_events.sql` for the events table (Admin Brand / Analytics tabs read via `GET /api/admin/analytics`).
- **Env:** Vite uses `VITE_*` (e.g. `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_API_BASE`, `VITE_ADMIN_EMAILS`). Backend uses `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_EMAILS`. **Stripe membership (optional):** `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_ID_3MONTHS` / `_6MONTHS` / `_12MONTHS`, `SITE_URL` — see `docs/STRIPE_MEMBERSHIP_SETUP.md`.
- **Local:** `.env.local` for dev; copy from `.env.example`. Restart dev server after changing env.

## Design system

- **Fonts:** "Futura PT" family (Book, Medium, Demi). "Covered By Your Grace" for accent numbers/dates. Uppercase labels and CTAs common.
- **Brand red:** `#EB1C24` — primary buttons, links, active states, key icons.
- **Backgrounds:** Marble texture (`/assets/marble-half.png`), white/translucent cards (`bg-white/60`, `backdrop-blur-sm`), borders often `1.3px solid black` or `1.3px solid #9ca3af` (gray).
- **Icons:** SVGs in `public/assets/` (e.g. `special-offer.svg`, `slay-challenge.svg`, `Free Gift.svg`). Use `<img src="/assets/...">` with red filter when they should match brand red.
- **Layout:** Mobile-first; shared nav with back/menu, breadcrumb-style text (e.g. `ACCOUNT > CONCIERGE`), cart icon, dynamic cart count from localStorage / events.

## Key flows

- **Account / Concierge:** Priority messages, order tracking, Slay Challenge (6‑month cycles, reward selection), Special Offer (configurable via Admin → Marketing; $40 off, 60‑day countdown), Free Gift, Birthday Gift. Founder-privileged admin can override Slay Challenge stage for testing.
- **Account → Rewards (premium chart) + subscription checkout:** The premium comparison chart and **CONFIRM SUBSCRIPTION** live on **Account → Rewards** at **`/account/rewards`** (`src/pages/account/membership/page.tsx`). Confirming navigates to **`/checkout/upgrade`** with the tier in `localStorage` (`subscriptionUpgrade`). **Subscribe with card (Stripe)** appears only on **`/checkout/upgrade`** (`src/pages/checkout/page.tsx`), not on Rewards, when **`GET /api/stripe/membership-available`** is **`available: true`** and the user has a **Supabase** session (`getAccessToken()`). Stripe success returns to **`/checkout/upgrade?stripe=success`**, then the app syncs profile and routes to Rewards. There is no separate nav item labeled “Membership.”
- **Admin / Marketing:** Special-offer config at **`/admin/marketing`** (nav: "ADMIN > MARKETING"). Page: product, length, density, texture, lace, hairline (incl. LAGOS + PEAK), color, styling (incl. Bangs combos), add-ons (dropdown with all combinations: NONE, single, BLEACH + PLUCK, etc., via `ADDON_COMBO_OPTIONS`), thumbnail, start date. All dropdown panels use `max-h-48 overflow-y-auto` for scrolling. Save Config and RANDOMIZE (red text) below card; RANDOMIZE fills all options with valid random values. **Persistence:** Save writes `specialOfferAdminConfig` to localStorage and upserts the same JSON to Supabase `app_config` key `special_offer_admin` via **`PUT /api/admin/special-offer-config`** (admin session). Concierge and the admin editor load from **`GET /api/special-offer-config`** first, then fall back to localStorage. **Newsletter tab:** After **SPECIAL OFFERS** — HTML email to clients with `notificationNewsletter` opt-in (Account → Settings); templates + recipient multi-select; **`POST /api/admin/newsletter-send`** (admin session) sends via **Resend** when **`RESEND_API_KEY`** (+ optional **`NEWSLETTER_FROM_EMAIL`**) are set on the server; up to 100 recipients per request (UI chunks larger sends).
- **Cart / Wishlist:** Stored in localStorage (global and per-user keys). Synced to backend on sign-in/sync where applicable. **BCF bundle-deal** lines (`bcfBundleDeal`): in the **shopping bag** they use the same controls as **A/C** booking lines — **QTY** label + **×** remove only (no **+ LIST**, no ± stepper, no **SAVE FOR LATER**). If the user **no longer qualifies** for premium-gated features (`isPremiumMemberForGatedFeatures` in `premiumMemberAccess.ts` — active premium subscription and/or **BLACK** spend tier), **`isPremiumGatedCartLine`** rows are **removed**: **bundle-deal**, all **`booking-appointment`** (hair installs), and **`booking-consult`** with **`bookingTier === 'premium'`** (standard consults remain). Same strip runs on **`cartItems`** / **`savedForLater`** load, **`signInStateChanged`** / **`focus`** (`applyStripIneligibleBcfBundleDealsToAllStoredCarts` in **`App.tsx`**), **`CartDropdown`**, **`/checkout`**, **`/checkout/summary`** (localStorage fallback), bag **`loadCartItems` / `loadSavedForLater`**. **`MOVE TO BAG`** from saved is blocked for any **`isPremiumGatedCartLine`** when not premium. **Booking:** **`/booking/premium/consultation`** (and **`/consult`**) — **add to bag** is blocked with **`ConfirmationModal`** unless **`isPremiumMemberForGatedFeatures()`** (same pattern as **`/booking/premium/appointment`** and **`/booking/appointment`**); SHOP menu routes non-premium users to standard **`/booking/consultation`** via **`bookingMenuUsesPremiumPaths()`** in **`bookingMemberRoutes.ts`**. **Build-a-wig:** options under **PREMIUM MEMBERSHIP OPTIONS** (lace, texture, color, hairline, styling, add-ons) require the same gate — hub **`handleOptionSelect`** shows upgrade modal; sub-routes use **`useBuildWigPremiumMembershipStepGate`** (`src/hooks/useBuildWigPremiumMembershipStepGate.tsx`). Categories list: **`buildWigPremiumOptions.ts`**.
- **Checkout order strip (shared with cart dropdown):** Horizontal cart tiles on **`/checkout`** and **`/checkout/summary`** use **`src/utils/checkoutOrderStripDisplay.ts`** — same thumbnail sizes/nudges and title/red line as **`CartDropdown`** (BCF shop lines, unit wigs, gift card, membership tiers). **A/C** = internal shorthand for **appointment + consult** booking cart lines (`booking-appointment`, `booking-consult`); titles **BOOKING** / **CONSULT**, badge thumbs **66px** in an **88px** slot (not the large header badge size).
- **Consult quote checkout codes:** Admin-sent **`CONSULT-*`** codes are validated with **`POST /api/checkout/validate-consult-code`** (signed-in owner, not expired, not redeemed); discount applies to non–booking cart subtotal on **`/checkout`** (not **`/checkout/bookings`**). After a successful order, **`POST /api/checkout/redeem-consult-code`** sets **`consult_quotes.redeemed_at`**. Migration **`20260403140000_consult_quotes_redeemed_at.sql`** adds **`redeemed_at`**. **Account → Orders** archived consult **VIEW OFFER** opens **`ConsultOfferClaimModal`** (thumbnail, breakdown, 72h timer, claim → bag + checkout auto-apply); **`markConsultOrderCompleteAfterQuoteSent`** can persist **`consultOfferSnapshot`** on the order for local/offline. **Admin meeting edits:** **`POST /api/admin/meeting-client-alert`** appends a client **notifications** item (reschedule vs cancel); **`AdminMeetingsHub`** uses **RESCHEDULE** / **CANCEL** buttons after **`PATCH`** notes. **Admin Meetings → Send offer:** dropdown option lists render in a **fixed-position portal** to **`document.body`** (high z-index) so lists are not clipped by the main card; default unit preview uses **`ordersPageUnitThumbnailSrcFromUnitKey`** in **`accountReviewProductThumbnail.ts`** (same 2D asset paths as Account → Orders wig list thumbs); optional **CUSTOM IMAGE:** picker (**`OrderFormFilePicker`**, same as order authorization) replaces the preview and persists a **`data:`** URL in the session draft and in **`thumbnailSrc`** / snapshot on send. Price breakdown amounts use a leading **`+`** for positive lines (including **UNIT**).
- **Consult-only checkout orders** (`bookingFlowType: 'consult'`): **`PLACED` → `PROCESSING`** after **2 hours** from **`placedAt`** (`CONSULT_PLACED_TO_PROCESSING_MS` in **`consultOrderLifecycle.ts`**); **`COMPLETE`** after **72h** from **`placedAt`** (same file). **Orders / confirm / Concierge** consult tracking bar: **`consultDigitalOrderTrackingBarFillPct`** in **`digitalOrderFulfillment.ts`** — **`PLACED`**: ~**10% → 30%** over the first **2h**; **`PROCESSING`**: **30% → 100%** over the remaining **70h** to the 72h window; **`COMPLETE`**: **100%**.
- **`/checkout/bookings`:** Nav crumb **CHECKOUT > BOOKING** (singular). Checkout logic treats **bookings-only** carts like **digital** for **shipping** (no ship address / calculator / method / delivery UI, no tax or loyalty points on that subtotal, billing required, package protection skipped) via **`checkoutSkipsShipping`** and **`isBookingsOnlyCheckoutState`** in **`utils/bookingCheckout.ts`**.
- **`/checkout/gift-card`:** Isolated gift-card checkout (bag filtered to gift lines). **First gift-card-only purchase per account** requires a **one-time** order-authorization-style flow (**`/tools/order-form`**, ID + signature): order rows get **`requiresGiftCardIdentityForm`**, **`digitalOrderFulfillment`** treats them as non-digital until signed; after submit, **`giftCardPurchaserIdentityVerified_{email}`** in localStorage skips repeat verification. Stored signed form for that flow is **`adminApproved: true`** immediately so it does not clog admin pending.
- **Orders:** Active/past orders per user; tracking stages with progress. Mock/test orders for admin (e.g. Kateena) for demos.
- **Admin → Pending (cross-device when Supabase + migration applied):** Server tables **`pending_order_forms`**, **`pending_affiliate_submissions`**, **`pending_review_supplemental`**, plus **`reviews`** rows with **`status = pending`**. Admin UI loads **`GET /api/admin/pending-queue`** (service role) and **`PATCH`** approve/decline updates DB + **`profiles.user_submitted_reviews`**, **`profiles.affiliate_submitted_content`**, **`profiles.signed_order_forms`**, **`profiles.review_supplemental_overlay`** (catalog/mock review ids), and **`orders`** where applicable. Clients POST **`/api/client/submissions`** (Bearer) for order form, review, supplemental media, affiliate batch; then **`syncProfileFromApi`** mirrors profile JSON into localStorage (**`clientPendingServerSync`**). **Migrations:** run **`20260413120000_pending_admin_queues.sql`** and **`20260414100000_profiles_review_supplemental_overlay.sql`** in Supabase SQL Editor. Without migration or session token, app falls back to prior **localStorage-only** mock queues.
- **Sync:** “Sync my account” (Settings) for any admin: sends Supabase email + password to `/api/admin/sync-profile`; backend returns profile, orders, cart, wishlist; frontend applies to localStorage. Requires admin email in both `VITE_ADMIN_EMAILS` and `ADMIN_EMAILS`.

## Conventions

- **Lobby (home) nav:** Neon logo (center) → `/home/shop`. Products (neon-products) → `/shop/units`. Tools (neon-tools) → `/home/tools`. Implemented in `src/pages/lobby/page.tsx`.
- **App default route:** `/` and the index route redirect to **`/home/shop`** (`App.tsx`), not `/shop/units`.
- **Paths:** Pages under `src/pages/` (e.g. `account/`, `account/settings/`, `account/concierge/`, `admin/`). Shared components in `src/components/`, utils in `src/utils/`.
- **State:** React `useState`/`useEffect`; persistent data in localStorage (`currentUser`, `registeredUsers`, cart, wishlist, per-user keys). Supabase session for server-backed data.
- **API:** Base URL from `VITE_API_BASE`; routes in `api/` (e.g. `api/admin/sync-profile`, `api/delete-account`). CORS and JSON error responses on API routes. **Checkout hardening (partial):** `POST /api/checkout/quote` recomputes USD from cart **identities** (booking, consult, simple unit names); `POST /api/stripe/create-product-payment-intent` creates a PaymentIntent from that total; webhook `payment_intent.succeeded` can append an order. Details: `docs/CHECKOUT_SERVER_QUOTE.md`. Currency selector remains display-oriented until server FX + charge currency are added.
- **Docs:** Project docs in `docs/` (e.g. `ADMIN_SYNC_SUPABASE_EMAIL_WALKTHROUGH.md`, `DELETE_ACCOUNT_API_WALKTHROUGH.md`). **Profiles:** Exact Supabase `profiles` columns and how they map to the API and app (name, photo, socials, birthday, rewards) are in `docs/PROFILES_COLUMNS_AND_APP_MAPPING.md`—use it when fixing sync or account repopulation.
- **Profile image:** **`POST /api/profile-image`** accepts a data URL, uploads to Storage bucket **`profile-images`**, then sets **`profiles.profile_image`** using the **service role** (after **`getAuthUser`** validates the JWT). Client PATCH/queue intentionally omit base64 blobs; persistence requires this upload path so **`GET /api/profile`** returns the URL after sign-in.
- **Admin client details (Orders vs Appointments):** Orders and Appointments tabs share the same card layout (flex, gap 12px), typography (Covered By Your Grace 16px for date, Futura PT Medium 10px/12px for title and secondary text, #EB1C24 / #808080), left 85×85 area (orders: product image + "N ITEMS"; appointments: APT placeholder only, no label below), status pill (height 15px, padding 0 6px, borderRadius 2px, Futura PT Medium 8px). Appointment time is offset with `translateY(-2px)`. Empty state: "NO APPOINTMENTS YET" matches "NO ORDERS YET" styling.
- **Client profile BIRTHDAY row:** Add BIRTHDAY between EMAIL and PHONE. Display format "AUGUST 30, 1989". Fallback order: birthDate → birthMonth+birthDay+birthYear (MM/DD/YYYY) → birthMonth+birthDay (MM/DD) → birthDay only ("Day 15") → "—". See MEMORY 2025-02-28.
- **Main card responsive height:** For the single main content card (border, bg-white/60, backdrop-blur-sm, p-4, mb-2) on list/settings-style pages: use proportional scaling so the card keeps the same visual proportion across viewports. **Wishlist lists** uses `calc(100vh * 520 / 745)` (520px at 745px viewport height). **Account Payment** and **Account Shipping** use `minHeight: calc(100vh * 510 / 900)`. Other pages (Wishlist main, Shopping bag, Admin clients, Account settings, Account menu open) use viewport-minus-fixed (e.g. `calc(100vh - 270px)` or `calc(100dvh - 160px)`). See MEMORY 2025-02-28 (main card responsiveness).
- **Branch policy (user preference — critical):** Implement, commit, and push **only on `preview/mobile`** unless the user **explicitly** names another branch. **Do not create** `cursor/*` or other side branches for this project: work is easy to miss on preview. Cloud agents may default to a named task branch; **override** and use **`preview/mobile`** unless the user says otherwise.
