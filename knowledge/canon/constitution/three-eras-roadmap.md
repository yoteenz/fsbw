# Three Eras Roadmap™

**Constitutional Article · Studio World Architecture**

---

## Article

Studio World™ evolves in **three sequenced eras**. No era may be skipped. No later-era system may become canonical truth before the prior era's memory substrate is established.

| Era | Name | Objective |
|-----|------|-----------|
| 1 | **Knowledge™** | Memory — Studio World understands itself |
| 2 | **World™** | Civilization — the graph drives a living, connected world |
| 3 | **Intelligence™** | Reasoning — proactive assistance over the graph |

**Current era:** Knowledge™ (ERA 1).

---

## Evolution law

```
Knowledge™ → World™ → Intelligence™
```

Knowledge creates memory. Memory creates relationships. Relationships create understanding. Understanding enables intelligence.

Build the foundation first. Then build the civilization. Then build the intelligence that operates it.

---

## Implementation gate

Every major implementation must be evaluated before code ships:

1. Which era does this belong to?
2. Does it establish a strong foundation for the next era?
3. Is this introducing unnecessary complexity too early?
4. Can this be designed so it naturally evolves into the next stage without requiring a rewrite?

Implementations that fail questions 3 or 4 must be deferred or redesigned. Implementations that store truth outside the World Graph™ violate World Graph Is Truth™.

---

## Corollaries

1. **Era 1 systems** register nodes, edges, lifecycle, and provenance — not parallel documentation stores.
2. **Era 2 systems** are projections and places over existing graph memory — not independent silos.
3. **Era 3 systems** read and reason over the graph — they do not replace it.
4. **Agents and motherboards** sync summaries into the graph; they do not define canon.
5. Full roadmap: `docs/studio-os/world-graph/STUDIO_WORLD_THREE_ERAS_ROADMAP.md`
