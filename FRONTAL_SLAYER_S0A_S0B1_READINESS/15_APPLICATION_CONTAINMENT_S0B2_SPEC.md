# 15 — S0B-2 Application Containment Specification

**Specification only. Nothing is implemented in this sprint.** Exact components, handlers and line ranges are in `evidence/S_app_containment_and_secrets.md`, with file:line throughout. That research corrected two earlier findings: **Build-A-Wig lines are charged at the wrong price, not blocked**, and the **Concierge injection reaches every signed-in customer**. Both corrections are folded in below.

## 0. Cross-cutting mechanism (engineering default)

Add one server flag, **`COMMERCE_CONTAINMENT=1`**, read by the money endpoints, and expose it through `GET /api/stripe/product-checkout-available` as `containment: true`. The client hides the contained purchase paths when `containment` is true **or when the availability call fails** (fail closed). Today a failed call falls through to client-only checkout (`src/utils/productCheckoutPolicy.ts:50-59`). Every item below can be switched back individually by environment variable.

**Experience authority rule:** these containments change checkout **behaviour** and **copy** only. They do not change the mobile or desktop/tablet visual systems. The desktop `/desktop/acquisition*` embeds the same `CheckoutPage` (`src/pages/desktop/acquisition/page.tsx:20-36`), so one server-side containment covers both experiences, and each keeps its own chrome.

## 2. Out of S0B-2 (not containment)

- Ledgers, server order of record, refunds (S1/S3/S4). Stripe-side remediation (A8 is blocked by evidence: the database holds 0 grants, 0 orders and 0 subscriptions, but Stripe history is unverified).
- Any visual redesign of mobile, desktop/tablet or admin.

## 3. Acceptance (S0B-2 gate)

- No client path grants premium, tickets, credits or cash. Static grep, plus Stripe test-mode E2E on staging.
- No undercharge: a BAW line cannot reach a PaymentIntent without a server-held amount (parity test).
- No fabricated customer or financial data in production builds (grep gate; manual pass of `/account/concierge`, `/slay-cam` and `/admin/dashboard` with a non-founder test account).
- Mobile and desktop/tablet each verified in their own experience: the mobile `/checkout` and the desktop `/desktop/acquisition`, separately.
- Each item can be switched back individually via `COMMERCE_CONTAINMENT` sub-flags.
