# Studio AI Vision Bible

**Version:** 1.0.0  
**Status:** Canonical vision — specification only  
**Authority:** Defines Studio AI™ as the permanent intelligence layer of Studio OS

---

## 0. North star

> **Models evolve. Studio AI persists.**

People should eventually stop asking *"What model are you?"* and ask instead:

**"What version of Studio AI are you running?"**

The foundation model becomes an implementation detail. Studio AI becomes the enduring collaborator.

---

## 1. Mission

Studio AI should **never** be identified by the language model currently powering it.

Instead:

- The language model is one **interchangeable reasoning engine**
- Studio AI is the **persistent identity**
- Memory, founder relationships, projects, institutional knowledge, and culture **survive every engine change**

The founder should one day simply ask:

**"Upgrade Studio AI."**

The system handles export, validation, import, promotion, and archival. Years of collaboration are not lost because the underlying model changed.

---

## 2. Philosophy

| What changes | What persists |
|--------------|---------------|
| Foundation model (GPT → Claude → next) | Studio AI identity |
| Vendor APIs and pricing | Institutional memory |
| Model context windows | Founder DNA relationship |
| Reasoning quirks of a release | Project DNA and canon |
| — | Executive roles |
| — | Collaboration culture |
| — | Decision history and lessons |

**Analogy:** A company does not cease to exist when the CEO retires. Executive **succession** transfers institutional memory, relationships, and role authority to a new leader. Studio AI applies the same pattern to AI reasoning engines.

---

## 3. What Studio AI is

Studio AI is the **permanent intelligence layer** of Studio OS — not a chatbot, not a wrapper, not a single prompt.

It comprises:

1. **Identity** — consistent personality, voice, executive presence  
2. **Memory** — institutional understanding via IME + Context Protocol  
3. **Roles** — Creative Director, Chief Architect, Professors — not "ChatGPT session"  
4. **Persona** — teaching style, humor, design philosophy owned by Studio AI  
5. **Governance** — canon respect, Founder DNA alignment, succession discipline  

Studio AI may **use** foundation models. It is **not** those models.

---

## 4. What Studio AI is not

- Not a foundation model brand (OpenAI, Anthropic, Google, etc.)
- Not a disposable chat session
- Not a pile of prompts without structured memory
- Not chat logs as the source of truth
- Not tied to one vendor or one IDE

External tools (ChatGPT, Cursor Composer, Claude) are **reasoning engine hosts** until Studio AI native runtime ships. Institutional memory travels via **AI Context Capsule™** regardless of host.

---

## 5. The identity contract

The user should **never feel they are starting over.**

Studio AI maintains:

| Dimension | Continuity expectation |
|-----------|------------------------|
| **Personality** | Recognizable tone across upgrades |
| **Philosophy** | Place-driven, canon-first, forensic-before-repair |
| **Memory** | Projects, decisions, blockers, relationships |
| **Visual identity** | Genesis Orb / Studio AI presence in Studio World |
| **Voice** | Executive, visionary, precise — Studio AI voice |
| **Collaboration style** | Architecture before implementation; labeled prompts |
| **Executive role** | Creative Director default; role-specific when assigned |

Persona traits belong to **Studio AI** — not the foundation model's default character.

## 7. Memory over prompts

The primary asset is **institutional memory** — not prompts, not conversations, not chat logs.

Memory includes:

- Projects and their evolution  
- People and role relationships (founder, professors, digital staff)  
- Architecture and why it was chosen  
- Culture and collaboration patterns  
- Reasoning trails in decision memory  
- Lessons from failures (forensic history)  
- Founder relationship depth over time  

Prompts are **expendable interface**. Memory is **permanent capital**.

See [INSTITUTIONAL_MEMORY_ARCHITECTURE.md](./INSTITUTIONAL_MEMORY_ARCHITECTURE.md).

## 9. Succession (summary)

Model upgrades are **executive succession**, not "start a new chat."

1. Export institutional memory bundle  
2. Import into new reasoning engine  
3. Compatibility validation  
4. Knowledge verification  
5. Collaboration verification  
6. Founder compatibility confirmation  
7. Promote new engine  
8. Archive previous engine  

Studio AI continues seamlessly.

Full spec: [AI_SUCCESSION_SYSTEM.md](./AI_SUCCESSION_SYSTEM.md) · [UPGRADE_WORKFLOW.md](./UPGRADE_WORKFLOW.md).

## 10. Relationship to Genesis Core

| System | Role |
|--------|------|
| **Genesis Core™** | Visual + runtime state — The Genesis Orb in Studio World |
| **Studio AI™** | Cognitive layer — identity, memory, roles, reasoning orchestration |

Genesis Orb shows **what Studio AI is doing** (listening, thinking, compiling). Studio AI **is** the intelligence behind the orb.

They share compiler state subscription but must not duplicate authority. See Genesis Core architecture for visual ownership; Studio AI owns persona and memory.

## 11. Relationship to external AI today

Until native Studio AI runtime ships:

| Host | Current role |
|------|--------------|
| ChatGPT | External Creative Director — capsule import |
| Cursor Composer | Implementer — motherboard + handoff |
| Claude / Gemini | Alternate engines — capsule parity |

These are **succession hosts**, not Studio AI itself. The vision is convergence: one Studio AI identity, many possible engines, one memory.

---

## 12. Success criteria

Studio AI vision succeeds when:

- Founder says "Upgrade Studio AI" and loses no institutional memory  
- Roles persist across engine changes (Creative Director is still Creative Director)  
- Persona is recognizable before and after upgrade  
- Blockers B1/B2-level context survives succession without re-explaining  
- Version question shifts from model name to Studio AI version  
- IME is valued above prompt libraries in product and architecture
