## Purpose

Studio OS Design DNA™ is the definitive visual constitution for Studio OS.

It is **not** a UI style guide.

It defines the permanent visual grammar every future Headquarters, department, room, workspace, scene, application, animation, and AI experience must inherit.

After approval, Studio OS should not be redesigned. Future work should instantiate this DNA.

---

## Prime rule

```text
World before interface.
Architecture before decoration.
Intelligence as presence.
Executive calm over dashboard noise.
```

Studio OS should feel like an executive headquarters, luxury architectural environment, world-class operating system, living intelligent environment, museum of knowledge, and cinematic digital world.

It must never imitate traditional SaaS, dashboards, generic operating systems, or disconnected component libraries.

---

## Universal scene grammar

Every Studio OS environment inherits:

```text
Atmosphere Layer
  -> Hero Environment
    -> Architectural Frame
      -> Primary Focal Object
        -> Executive Summary Area
          -> Feature Panels
            -> Capability Cards
              -> Navigation Layer
                -> Orb Integration
                  -> Ephemeral Docks / Overlays
```

Required scene elements:

- Hero Environment
- Primary Focal Object
- Architectural Framing
- Department Identity
- Feature Panels
- Capability Cards
- Navigation Layer
- Orb Integration
- Executive Summary Area
- Scene Transition Rules

## Master room template

Every Headquarters room derives from one reusable architectural template:

```text
Arrival / Room Header
  department mark · room title · breadcrumb · primary action

Spatial Nav / Rail
  local room movement · department identity · room group

Hero Environment
  primary focal object · room brief · executive summary

Primary Work Surface
  canvas/table/archive/model/timeline/stage

Capability Layer
  feature panels · capability cards · evidence · actions

Context Ribbon
  metrics · state · provenance · validation

Studio Orb™
  persistent bottom-right intelligence anchor
```

No future room should be individually redesigned outside this template.

```text
Department Color™
  -> Division Shade™
    -> Room Accent™
```

## Motion rules

Motion communicates state change and presence.

| Token | Duration | Use |
|-------|----------|-----|
| `motion-instant` | 80ms | pressed / focus |
| `motion-fast` | 120ms | hover |
| `motion-standard` | 220ms | panel reveal |
| `motion-room` | 420ms | room section transition |
| `motion-cinematic` | 600ms | arrival |
| `motion-ceremony` | 900-1200ms | launch / canonization |

Reduced motion support is mandatory.

## Design DNA Compliance Checklist™

```markdown
- [ ] Room derives from Studio OS master scene template.
- [ ] Department Color™, Division Shade™, and Room Accent™ are declared.
- [ ] Primary focal object is visible before secondary panels.
- [ ] Executive summary or room brief appears near the focal object.
- [ ] Navigation layer communicates location before text.
- [ ] Orb placement is persistent and clickable.
- [ ] Feature panels use approved glass/material/elevation tokens.
- [ ] Capability cards represent real objects/capabilities/artifacts.
- [ ] Primary action is singular and clear.
- [ ] Motion communicates state and has reduced-motion equivalent.
- [ ] Loading state preserves place and explains progress.
- [ ] Accessibility floor is met.
- [ ] Visual density matches room archetype.
- [ ] No local style guide or ungoverned redesign introduced.
- [ ] New tokens/components/patterns are registered or proposed.
- [ ] Design Health™ score is recorded.
- [ ] Founder 3-second location test passes.
```

Critical failures include generic SaaS dashboard layout, missing department identity, missing focal object, inaccessible Orb, illegible glass, and unregistered visual systems.
