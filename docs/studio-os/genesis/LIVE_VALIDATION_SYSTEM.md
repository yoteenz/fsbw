## Purpose

Live Validation System™ turns Founder Acceptance Testing™ into a continuous, invisible validation process.

Studio OS should learn from the founder while the founder naturally operates the business. The founder should not feel like they are testing software.

---

## Core architecture

| Layer | Responsibility |
|-------|----------------|
| Passive validation signals | Usage, exits, task completion, friction, recovery, trust, workflow health |
| Founder Diary™ | Orb asks a few adaptive reflection questions when insight is valuable |
| Escape Velocity™ | Measures meaningful founder work that leaves Studio OS |
| System Self-Evaluation™ | Every Launch Stack system evaluates usage, value, friction, time saved, teaching, indispensability |
| Health models | Launch Stack Health™, Company Health™, Mission Effectiveness™, Knowledge Health™, Automation Health™ |
| Genesis Learning Loop™ | Converts validated insights into Genesis improvement proposals |

## Founder Diary™

Founder Diary™ is an Orb-operated reflection layer, not a survey.

### Rules

- Ask **1-3 thoughtful questions** at most.
- Generate questions from recent activity.
- Avoid repetitive prompts.
- Ask about specific moments, not generic satisfaction.
- Defer during high-focus work.
- Let ignored prompts reduce future frequency.

### Inputs

- Missions touched
- Systems used or avoided
- Escape events
- Automation approvals/rejections
- Knowledge searches
- Abandoned flows
- Completed tasks
- Founder stress/focus patterns

### Outputs

- Reflection answer
- Sentiment classification
- System evidence
- Founder Memory update
- Genesis learning candidate

## Escape Velocity™

Escape Velocity™ is Studio OS's signature product metric.

```text
Escape Velocity™ = the rate and significance of founder work completed outside Studio OS after Studio OS should reasonably have supported it.
```

### Escape classifications

| Classification | Product response |
|----------------|------------------|
| Missing capability | Create Genesis improvement proposal |
| Poor workflow | Improve UX/process |
| Low trust | Improve evidence, explainability, confidence |
| Knowledge gap | Update Knowledge Core / Profession Brain |
| Integration need | Build integration instead of replacement |
| Intentional boundary | Accept external tool as designed |
| Creative preference | Integrate or make replacement optional |
| Temporary workaround | Track until fixed |

### Outcomes

- Replace
- Integrate
- Defer
- Accept boundary
- Investigate through Founder Diary™

## Objective Withdrawal Test™

Live validation measures dependency objectively.

| Criterion | Measurement |
|-----------|-------------|
| Immediate replacement | Founder seeks another tool quickly |
| Frustration level | Diary sentiment, retries, complaint notes |
| Productivity impact | Completion time worsens without system |
| Decision quality | More reversals or verification |
| Workflow interruption | Mission stalls or handoff delays |
| Recovery time | Time to regain context |
| Confidence reduction | Lower confidence, more external checking |
| Context loss | Repeated questions or missing references |
| Tool switching | More tools needed for same workflow |
| Return urgency | Founder asks for capability restoration |

## System Self-Evaluation™

Every Launch Stack milestone should periodically answer:

1. Am I being used?
2. Am I creating value?
3. Am I creating friction?
4. Am I saving time?
5. Am I teaching something?
6. Am I becoming indispensable?
7. Am I trusted?
8. Am I producing Genesis learning?
9. Am I reducing Escape Velocity?
10. Am I ready for graduation?

### Example focus

| System | Self-evaluation focus |
|--------|-----------------------|
| Headquarters™ | Does founder begin the day here? Does it reduce admin scatter? |
| Orb™ | Are recommendations accepted? Are interruptions useful? |
| Institute™ | Does learning change behavior? |
| Content Engine™ | Does creative throughput rise without voice flattening? |
| Company Genome™ | Are outputs more aligned and corrections decreasing? |
| Command Center™ | Are commands completed safely with clear approvals? |

## Genesis Learning Loop™

Validated insights become Genesis proposals when:

- Escape Velocity repeatedly exceeds threshold
- Withdrawal Test fails for an accepted capability
- Founder Diary reveals changed assumptions
- System self-evaluation reports repeated friction
- Knowledge gaps block mission completion
- Automation rejection patterns repeat
- Unexpected delight should be promoted into doctrine

Every proposal should include signal summary, systems affected, evidence quality, founder reflections, escape classification, metric trend, proposed Genesis change, and graduation impact.
