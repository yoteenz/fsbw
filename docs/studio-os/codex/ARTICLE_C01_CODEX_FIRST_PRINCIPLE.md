---

## Origin

Studio World reached a level of complexity where implementation can no longer safely precede documented architectural memory.

Major features now affect many systems at once: World Graph™, Knowledge Core™, Production Orchestrator™, Career Worlds™, Asset Compiler™, Studio Foundry™, Hero Objects™, Profession Brains™, governance, design language, and future eras.

If an idea exists only in a chat, branch, prompt, or implementation, it can be lost, misremembered, duplicated, contradicted, or rebuilt incorrectly.

Therefore:

> **Every major Studio World feature must become a Codex Article™ before implementation begins.**

---

## Purpose

The Studio World Codex™ is the constitutional memory of Studio World.

It exists to preserve:

- philosophy,
- systems,
- feature intent,
- laws,
- naming conventions,
- architecture,
- design language,
- production standards,
- profession knowledge,
- Career Worlds,
- Knowledge Core decisions,
- long-term vision.

The Codex must outlive any individual AI model, conversation, implementation, contributor, or release.

---

## Core Philosophy

The Codex is not documentation.

Documentation explains what exists.

The Codex defines what Studio World believes, why systems deserve to exist, how they connect to the civilization, and how future builders must evolve them.

**The Codex is Studio World remembering itself before it builds.**

---

## Guiding Principles

1. **Codex before code.** Major features begin as Codex Articles, not implementation files.
2. **Canon before convenience.** Speed does not justify bypassing constitutional memory.
3. **Ideas must explain why they exist.** Implementation starts only after purpose, philosophy, and system connections are clear.
4. **One-off features should be challenged.** Every major idea must ask whether it should become a reusable platform capability.
5. **Memory is infrastructure.** Studio World should never depend on a single conversation or AI model remembering the architecture.
6. **The Codex evolves.** Production learnings update articles after launch.
7. **The world is coherent.** Every feature belongs to a larger civilization, not an isolated backlog.

### Stage responsibilities

| Stage | Responsibility |
|-------|----------------|
| Idea | Preserve the initial spark without committing to implementation. |
| Exploration | Ask whether the idea strengthens Studio World. |
| Architectural Evolution | Define system ownership, boundaries, dependencies, and future paths. |
| Codex Article™ | Convert the idea into canonical structure. |
| Constitution Review™ | Check principles, physics, laws, standards, and risk. |
| World Bible™ | Project approved truth into founder-facing world canon. |
| Implementation Plan™ | Translate article into engineering scope. |
| Engineering | Build only after article approval. |
| Production | Ship through Production Completion System™ gates. |
| Post-Launch Review | Capture what reality taught the system. |
| Codex Update™ | Revise the article so canon stays alive. |

## Canonical Thinking™

Every new major idea must answer:

1. **Why should this exist?**
2. **How does it strengthen Studio World's philosophy?**
3. **How does it connect to existing systems?**
4. **What future systems naturally evolve from it?**
5. **Could this become a reusable platform capability instead of a one-off feature?**

Only after these answers are documented should implementation begin.

---

## Architectural Implications

### Knowledge Core™

Knowledge Core™ remains the searchable institutional memory, but major approved ideas must now be represented as Codex Articles before they influence implementation.

### World Graph™

World Graph™ should register the Codex engine, Codex volumes, and major Codex Articles so canonical relationships are queryable.

### Architecture Decision Records™

ADRs preserve decision history and tradeoffs. Codex Articles define the approved constitutional idea. ADRs may support, challenge, supersede, or explain implementation choices for Codex Articles.

### World Bible™

World Bible™ becomes the narrative projection of Codex-approved truth, not a parallel source of truth.

### Production Completion System™

Major implementation work should not pass architecture checkpoints unless it references the relevant Codex Article.
