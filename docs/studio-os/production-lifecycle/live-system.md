# Live™ — Headquarters Operations Stage

**Lifecycle Stage:** 4 of 6  
**Status:** Canonical  
**Predecessor:** Certified™  
**Successor:** Evolution™ (continuous)

---

## Purpose

Live™ is when an experience **officially joins Headquarters**.

Real founders begin using it. Real analytics begin. Real learning begins.

Certified™ proved quality. Live™ proves **value in daily operations**.

---

## What Live™ Means

| Live™ Is | Live™ Is Not |
|----------|--------------|
| Default founder-facing experience | Beta · preview · hidden flag |
| Analytics-active | Silent deployment |
| Participating in daily operations | Demo-only |
| Evolution-enabled from day one | Frozen release |

---

## Headquarters Integration

When an experience goes Live™:

```
certificationToken validated
         ↓
Headquarters navigation updated
         ↓
Department / pack / feature surfaced to founders
         ↓
Studio Intelligence™ indexing begins
         ↓
Analytics + learning pipelines active
         ↓
Daily Operations™ eligible
         ↓
LIVE™
```

## Relationship to Certified™

| Certified™ | Live™ |
|------------|-------|
| Quality proof | Operational deployment |
| Blocking gate | Requires certification |
| May be reviewed offline | Founder daily use |
| Badges displayed | Default experience |

**Nothing becomes Live™ without Certification.**

---

## Exit Criteria

Live™ has no exit — it **flows continuously into Evolution™**.

Deprecation or replacement triggers Legacy™ ceremony — not a "Live™ exit."

---

## Anti-Patterns

| Anti-pattern | Why forbidden |
|--------------|---------------|
| "Soft Live" without certification | Violates lifecycle law |
| Hiding Live status from founders | Breaks dual-awareness principle |
| Freezing Live experiences | Evolution™ is mandatory |
| Removing without Legacy™ ceremony | Abandonment — not lifecycle |

---

## Transition

**Live™ → Evolution™** is automatic and continuous from launch.

Historic replacement: **Evolution™ → Legacy™** via ceremony.
