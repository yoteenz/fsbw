# Scene Framework™

**Focused Workspaces — Not Screens**

---

## Purpose

Define what a **Scene™** is — the navigable place inside a department where one class of work happens.

---

## Core Law

**A Scene™ is a workspace with a single clear purpose.**

Scenes exist because work happens there. Never because another page was needed.

---

## Scene Definition

| Property | Requirement |
|----------|-------------|
| **Purpose** | One sentence: what work happens here |
| **Separation** | Distinct from adjacent scenes — justified |
| **Physical anchor** | Furniture · architecture · equipment |
| **Emotional state** | How founder should feel |
| **Attention hierarchy** | Hero object · background systems |
| **Entry affordance** | How founder arrives at this scene |
| **Exit affordance** | Natural next scene or return path |

---

## Scene vs Page vs Route

| Concept | Nature |
|---------|--------|
| **Page** | Web artifact — **forbidden mental model** |
| **Route** | Implementation transport — non-canonical |
| **Scene™** | Canonical place in Studio World™ |

```
Route /admin/studio/department/creative-direction  →  expresses  →  Department destination
Camera zone / panel inside room                    →  expresses  →  Scene™ (prototype era)
Future Scene Runtime                               →  expresses  →  Scene™ (target era)
```

---

## Scene Inventory Pattern

Every department maintains a **scene inventory**:

```
Department™
├── Arrival Scene™          (mandatory — entry)
├── [Primary scenes]        (core work)
├── [Secondary scenes]      (supporting work)
├── [Discovery scenes]      (exploration · depth)
└── Departure Scene™        (exit transition)
```

### Mandatory Scenes

| Scene | Every department |
|-------|------------------|
| **Arrival Scene™** | Yes — threshold · partial reveal |
| **Orb presence** | Yes — host available in department |
| **Departure / Exit** | Yes — transition to next destination |

---

## Scene Design Checklist

Before a scene exists, it must answer:

| # | Question | Pass criteria |
|---|----------|---------------|
| 1 | Why does this place exist? | Clear business reason |
| 2 | What work happens here? | Named activities |
| 3 | Why separated from previous scene? | Cognitive · spatial · workflow justification |
| 4 | What emotional state? | One primary feeling |
| 5 | What draws attention first? | Hero object identified |
| 6 | What stays in background? | Ambient · non-interactive |

## Scene Navigation Inside Department

Founders move between scenes via:

| Movement | When |
|----------|------|
| **Walk** | Default exploration |
| **Camera dolly** | Arrival · scene focus |
| **Pan** | Wide scenes (Mood Wall · gallery) |
| **Station select** | Mobile · accessibility |
| **Orb route** | "Take me to the pipeline board" |

**Forbidden:** Vertical page scroll across scenes.

**Source:** [movement-philosophy.md](./movement-philosophy.md)

---

## Scene Persistence

Scenes remember:

| Memory | Source |
|--------|--------|
| Last visited scene | World Memory™ |
| In-progress work | Project Genome™ |
| Scene-specific state | Scene state store |
| Founder position | Department camera restore |

Returning founders resume where they left — with abbreviated arrival.

---

## Scene and Set™ Relationship

```
Set™ (Creative Atelier™)
  contains
    Scene™ × N (Mood Wall · Story Table · Pipeline · …)
      contains
        Workspace™ × 0..M
```

A Set™ **transforms** per company ([Living Sets™](../world/living-sets.md)).

Scenes **persist** as framework zones — expression changes, purpose does not.

## Scene Naming Convention

```
[Function] Scene™
[Object] Scene™        (when object IS the scene)
[Activity] Scene™      (when activity names the place)
```

Examples: `Mood Wall Scene™` · `Interview Studio Scene™` · `Launch Center Scene™`

---

## Anti-Patterns

| Anti-pattern | Replacement |
|--------------|-------------|
| Scene = full-screen modal | Physical place in Set™ |
| Scene = tab in department | Walk to station |
| Scene without physical anchor | Not a valid scene |
| Scene that duplicates another | Merge or justify separation |
| Scene added for one button | Interaction™ at existing scene |
