# Routine Memory™

**Company Memory™ — Every Journey Teaches the System**

---

## Purpose

Define how completed and in-progress Routines™ become **persistent intelligence** — making future journeys smarter and more personal.

---

## Core Law

Every completed Routine™ becomes part of **Company Memory™**.

The headquarters remembers how this company works.

---

## What Gets Remembered

| Memory type | Content | Used for |
|-------------|---------|----------|
| **Completion record** | Routine · date · duration · outcome | History · chronicle |
| **Decision patterns** | Approve fast · compare three · sleep on it | Shortcut · recommendation |
| **Creative preferences** | Lighting before architecture · editorial tone | Taste adaptation |
| **Approval behavior** | Braintrust always · trust instinct sometimes | Review routing |
| **Timing patterns** | Average step duration · bottlenecks | Duration estimates |
| **Workflow favorites** | Most-used routines · skipped steps | Personalization |
| **Bottleneck map** | Where routines stall | Proactive Orb help |
| **Founder habits** | Morning creative · afternoon ops | Daily suggestions |
| **Artifact lineage** | What was created per routine | Reuse detection |

---

## Memory Layers

```
Routine Memory™
    ├── Session memory     (current · paused routine)
    ├── Company memory     (this company's patterns)
    └── Founder memory     (cross-company · Taste Genome™)
```

| Layer | Storage concept | Source |
|-------|-----------------|--------|
| **Session** | Resume stack | [resume-system.md](./resume-system.md) |
| **Company** | Company Genome™ extension | [Founder Intelligence™](../intelligence/README.md) |
| **Founder** | Founder Taste Genome™ | [Founder Taste Engine™](../founder-taste-engine/README.md) |

---

## Learning Triggers

Memory updates on:

| Event | Learning extracted |
|-------|-------------------|
| **Routine Complete™** | Full journey profile |
| **Step skipped** | Shortcut validity confirmed |
| **Step delayed** | Bottleneck signal |
| **Regeneration requested** | Taste mismatch signal |
| **Branch selected** | Comparison preference |
| **Routine abandoned** | Friction signal |
| **Routine resumed** | Commitment pattern |

---

## Founder Taste™ Integration

Routine Memory™ feeds [Founder Taste Engine™](../founder-taste-engine/README.md):

| Learned pattern | Future behavior |
|-----------------|-----------------|
| "Reviews lighting before architecture" | Reorder routine steps suggest |
| "Publishes after sleeping on Golden Build" | Delay distribution step suggest |
| "Compares three concepts before approving" | Pre-load three branches |
| "Skips analytics setup" | Offer shortcut · confirm once |

Studio OS quietly adapts — founder confirms or rejects via Orb.

---

## Privacy and Canon

| Rule | Law |
|------|-----|
| Memory serves founder | Not surveillance |
| Patterns are suggestions | Never forced |
| Alternate paths preserved | Canon vs branches |
| Cross-company taste travels | Company Genome™ does not |

---

## Memory Retrieval

Orb and Routine Engine™ query memory for:

| Query | Response |
|-------|----------|
| "Have we done this before?" | Prior routine instances |
| "What took longest last time?" | Bottleneck history |
| "What did we decide?" | Decision carry-forward |
| "What's my usual path?" | Personalized step order suggest |

---

## Anti-Patterns

| Anti-pattern | Why |
|--------------|-----|
| Memory without consent confirm | Founder must own adaptations |
| Forgetting completed work | Must enable shortcuts |
| Memory only in session | No learning |
| Routine history as analytics dashboard | Diegetic · Orb-narrated |
