# Routine Philosophy™

**Outcomes — Not Features**

---

## Purpose

Define the master philosophy of **Routines™** — how founders experience work as guided journeys through Studio World™.

---

## Core Declaration

```
FEATURES     →  disconnected software modules     (FORBIDDEN mental model)
NAVIGATION   →  walking between places             (Scene Architecture™)
ROUTINES™    →  guided journeys toward outcomes    (THIS SPRINT)
```

---

## What a Routine™ Is

| Routine™ **is** | Routine™ **is not** |
|-----------------|---------------------|
| A complete business objective journey | A wizard or onboarding flow |
| Orb-guided orchestration across departments | A checklist in a sidebar |
| Intelligent adaptation over time | A static script |
| Resumable work with memory | A one-shot modal |
| The OS asking *what* not *where* | Feature discovery |

---

## The Founder's Question Shift

| Software era | Studio OS era |
|--------------|---------------|
| "What feature do I open?" | "What am I trying to accomplish today?" |
| "Where is that setting?" | "I need to launch the product" |
| "How do I navigate to X?" | "The Orb will take me there" |
| "Did I finish the workflow?" | "The routine is complete" |

---

## Routine vs Navigation vs Task

| Layer | Scope | Example |
|-------|-------|---------|
| **Goal™** | Business outcome | Launch Product™ |
| **Routine™** | Multi-department journey | Launch Product Routine™ |
| **Department™** | Destination leg | Creative Direction Studio™ |
| **Scene™** | Place within leg | Story Table Scene™ |
| **Workspace™** | Activity | Asset Creation Workspace™ |
| **Task™** | Atomic action | Approve Golden Build™ stage |
| **Completion™** | Routine done | Routine Complete™ |

---

## Work Becomes a Journey

A routine is not a path through menus.

It is a **story** the founder lives inside Studio World™:

```
Arrive → Understand context → Do meaningful work →
Transition physically → Next department awakens →
Complete objective → Memory preserved → Smarter next time
```

## Routine Start™ Law

Every routine begins with an **Arrival Scene™**.

The founder never spawns in the middle of work.

| Beat | Content |
|------|---------|
| **Arrival** | Threshold · orientation |
| **Greeting** | Orb welcomes by name |
| **Context** | Why this routine now |
| **Objectives** | What will be accomplished |
| **Duration** | Estimated time |
| **Dependencies** | What must exist first |
| **Recent changes** | What changed since last visit |

Then the journey begins.

---

## Intelligence Over Rigidity

Routines are **guided** — not **railroaded**.

| Principle | Behavior |
|-----------|----------|
| **Intelligent Shortcuts™** | Skip completed work |
| **Reuse** | Existing assets carry forward |
| **Carry forward** | Prior decisions still apply |
| **Adaptation** | Routines smarter over time |
| **Interruption** | Leave anytime · resume exactly |
| **Discovery** | Explorer Mode™ always available |

**Source:** [routine-adaptation.md](./routine-adaptation.md) · [resume-system.md](./resume-system.md)

## Routine Memory™

Every completed Routine™ becomes part of **Company Memory™**.

The system learns:

- Decision patterns
- Creative preferences
- Approval behavior
- Average completion time
- Favorite workflows
- Common bottlenecks
- Founder habits

Future routines become increasingly personalized.

**Source:** [routine-memory.md](./routine-memory.md) · [Founder Taste Engine™](../founder-taste-engine/README.md)

## Long-Term Vision

Studio OS should feel less like opening software — and more like **beginning a workday**.

```
The founder arrives.
The Orb greets them.
The headquarters is already alive.
Today's priorities are waiting.
The founder simply begins.
```

---

## Anti-Patterns

| Anti-pattern | Why rejected |
|--------------|--------------|
| Routine = linear form wizard | Software not headquarters |
| Routine without Arrival Scene™ | No context · no ceremony |
| Routine that ignores completed work | Wastes founder time |
| Routine that cannot be interrupted | Prison not journey |
| Routine as only mode | Must support Explorer Mode™ |
| Feature checklist as routine | Outcomes not tasks |
