# Marketplace Transition System™

**Transitions™ as installable architectural identity**

---

## Vision

Every Headquarters can share the **same Studio OS engine** while expressing a **unique architectural journey**.

The **Marketplace** supplies **Transition DNA™** packages — hallways, elevators, bridges, corridors, vaults, galleries — that founders and designers install between Sets™ without forking the platform.

---

## What a marketplace transition is

A **Marketplace Transition™** is a **bundled asset** containing:

| Asset | Contents |
|-------|----------|
| **Transition DNA™** | `transition-dna.json` — type, duration, speed, lighting, audio, signage, orb hooks |
| **Camera choreography** | Keyframes / curves for the journey |
| **Environmental shell** | Geometry or 2.5D layer kit (hallway mesh, elevator cab, bridge span) |
| **Lighting profile** | Preset + state variants |
| **Audio profile** | Ambient loop + one-shots + optional narration stems |
| **Signage kit** | Department plaques, wayfinding, floor indicators |
| **Orb script pack** | Default contextual lines + slot templates |
| **Preview media** | Short loop for Marketplace card |
| **Certification metadata** | Performance tier, accessibility notes, engine version |

**Not included:** destination Set™ content — transitions are **connective tissue**, not departments.

## Installation model

```
Headquarters Map
    │
    ├── Edge: Creative Atelier™ ──► Discovery Lab™
    │         default: Glass Hallway™ (bundled)
    │         marketplace override: Japanese Garden Path™ (installed)
    │
    └── Edge: Marketing War Room™ ──► Finance Vault™
              default: Executive Corridor™ + Security Checkpoint™
              marketplace override: Industrial Factory Walkway™ (thematic rebrand)
```

**Rules:**

1. **One active Transition DNA™ per edge** (origin Set™ → destination Set™).
2. **Overrides** are per-company — Genome™ and permissions still apply.
3. **Bundled defaults** ship with Studio OS; Marketplace extends the library.
4. **No code fork** — install is data + media + certification stamp.

---

## Compatibility matrix

| Factor | Requirement |
|--------|-------------|
| **Transition type** | Edge must support type (e.g. no Elevator™ between same-floor-only link unless map defines shaft) |
| **Duration budget** | Certified™ max duration per device tier |
| **Performance tier** | Low-end SKUs flagged; may downgrade effects |
| **Accessibility** | Reduced motion variant required for Certified™ |
| **Engine version** | Manifest `minEngineVersion` |
| **Set DNA™ adjacency** | Optional `compatibleMoods[]` — warning if clash, not hard block |

## Certification pipeline

Marketplace transitions pass the same rigor as Sets™:

```
Submit → Validate DNA schema → Performance bench → Accessibility pass
    → Preview QA → Certified™ badge → Publish
```

**Quality gates:**

- No black-frame loaders
- Streaming within SLA
- Orb scripts reviewed (no misleading authority claims)
- Audio loudness normalized
- Camera reduced-motion path tested

---

## Genome™ integration

Installed transitions still **inherit**:

- Company Genome™ palette and signage typography
- Department personality on **destination** signage
- Founder Journey™ phase (onboarding vs mastery)
- Business state (Launch Day™, Celebration™, Crisis™)
- Time of day (lighting/audio variants)

**Marketplace shell** provides architecture; **Genome™** provides company soul.

## Relationship to Sets™ marketplace

| Asset | Role |
|-------|------|
| **Set™** | Destination room / department environment |
| **Transition™** | Journey between two Sets™ |
| **Object™** | Prop inside a Set™ |

Bundles may sell **Headquarters packs**: Sets™ + matching transition library (e.g. “Luxury Hotel HQ Pack”).

---

## Anti-patterns

| Anti-pattern | Why |
|--------------|-----|
| Transition that is only a spinner skin | Violates philosophy |
| Per-company engine fork | Unmaintainable |
| Transition that embeds full Set™ | Wrong asset type |
| Uncertified heavy SKU on mobile default | Performance betrayal |

---

## Summary

**Marketplace Transition System™** makes architectural identity **pluggable**: the engine stays one; the journeys multiply. Founders install hallways and elevators the way they choose furniture — except every choice reshapes how it *feels* to walk the company.
