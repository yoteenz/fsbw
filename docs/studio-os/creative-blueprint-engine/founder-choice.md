# Founder Choice™ — Blueprint Before Generation

**Module:** `studio.creative-blueprint.v1.founder-choice`  
**Status:** Generation is the final option

---

## Law

> When generating a new department, generation should always be the final option.

Studio OS asks about **Blueprint™** before **Assets™**.

---

---

## Four Choices

| Choice | When | Provider |
|--------|------|----------|
| **Apply Existing™** | Active blueprint fits department | Gap-fill only via Asset Intelligence |
| **Duplicate Blueprint™** | Need independent evolution fork | None for blueprint copy · gap gen |
| **Create Variant™** | Same DNA · different department expression | Parameter tune · optional partial gen |
| **Generate Completely New™** | Novel visual direction | Full blueprint + asset pipeline |

---

## Apply Existing™ (Default)

```
Inherit Visual DNA™ + Blueprint™ + Systems™
    ↓
Asset Intelligence links blueprint-bound assets
    ↓
Generate only missing assets (gaps)
    ↓
Department live with inherited language
```

Fastest path · highest coherence.

---

## Duplicate Blueprint™

```
Fork blueprint:editorial-luxury-v1
    → blueprint:editorial-luxury-marketing-fork-v1
    ↓
Independent evolution lineage
    ↓
Same systems initially · diverge via evolution
```

Use when department needs **long-term** distinct language under same Visual DNA™.

---

## Create Variant™

```
Same blueprint ID lineage
    ↓
Declare variant: accent-open
    ↓
System parameter overrides (brightness · openness)
    ↓
Shared asset bindings where possible
```

Use for **department flavor** without full fork.

---

## Generate Completely New™

```
No suitable blueprint above compatibility floor
    OR founder explicit novel direction
    ↓
Visual DNA™ selection or new archetype proposal
    ↓
Blueprint authoring (systems bundle)
    ↓
Asset generation for full manifest
```

Logged as `blueprintOverride: true` — teaches taste · not penalized.

---

## Stacked Gates

Full new department path:

```
1. Blueprint Founder Choice™     (this module)
2. Asset Intelligence gate       (per-gap reuse)
3. Creative Approval Pipeline™ (per new asset)
```

Apply Existing™ may skip gates 2–3 for fully bound blueprints.
