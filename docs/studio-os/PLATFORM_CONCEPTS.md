# studio os Platform Concepts

**Updated 2026-07-07:** [Headquarters Engine™](./headquarters-engine.md) platform philosophy.

## Operating System Metaphor

studio os is to **businesses** what an OS is to applications:

- **Kernel** — workspace context, routing, storage scoping, module registry
- **Headquarters Engine** — generates and evolves immersive business environments (spec)
- **Drivers** — service stubs (OpenAI, Fal, Resend, publishing) in `STUDIO_SERVICE_REGISTRY`
- **Expansions** — business capabilities installed into Headquarters — not apps
- **User space** — Workspace brand configuration, buildings, departments, Projects

Founders **step inside their Headquarters** — they do not "open software."

## Canonical object hierarchy

```
Headquarters → Buildings → Departments → Workspaces → Projects → Assets → Tasks
```

## Extensibility

1. **New Workspaces** — register config + data adapter → new Headquarters instance
2. **Headquarters Expansions** — install departments, workflows, AI specialists into existing HQ
3. **Headquarters Marketplace** — creators publish operational architecture for install
4. **New Core modules** — add to registry; must map to Headquarters hierarchy — never parallel app stores
5. **Workspace overrides** — atmosphere, module copy, data adapter, brand rules

## Scalability Targets

studio os architecture supports unlimited Workspaces, Headquarters layouts, Expansions, departments, Projects, and asset libraries — each isolated by Workspace ID.

## Industry Agnostic Core

Core modules use **Headquarters · Expansion · Project** language. Industry-specific headquarters types (Salon, Law Firm, Restaurant, …) are generated by Headquarters Engine — not hard-coded SaaS verticals.

Beauty, hair, PSA, Lounge TV, and e-commerce references exist only in the Frontal Slayer Workspace config and data adapter.
