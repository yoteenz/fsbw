# Visitor Interaction Model™

**Status:** Canonical visitor architecture — P0 Foundation Sprint  
**Scope:** Future external collaborators · clients · agencies · partners

---

## Visitor Thesis

> **Visitors become collaborators. The environment becomes the presentation.**

Studio World™ eventually invites designers, photographers, agencies, and clients **into the headquarters** — not into a PDF, not into a shared link, not into a video call.

The headquarters **is** the deliverable.

---

## Visitor Philosophy

| Old paradigm | Studio World™ paradigm |
|--------------|------------------------|
| Export PDF deck | Walk visitor through gallery |
| Share Figma link | Invite to Art Direction Studio™ |
| Email approval request | Seat visitor in Review Theater |
| Video call presentation | Co-present in Presentation Theater™ |
| Dropbox folder | Guide through Archive Vault (scoped) |
| Client portal login | Visitor arrival at Visitor Atrium™ |

## Visitor Types

### Type 1 — Client

**Relationship:** Pays for creative outcome · limited internal visibility.

| Attribute | Definition |
|-----------|------------|
| **Entry** | Visitor Atrium™ → guided path |
| **Visibility** | Approved work · curated milestones · presentation rooms |
| **Hidden** | Rejection archives · internal debate · taste genome |
| **Collaboration** | Review Theater seating · pointer approval · comment annotations |
| **Duration** | Session-scoped · no persistent desk |
| **Narrative** | Polished · intentional · confidence-building |

### Type 2 — Agency Partner

**Relationship:** Collaborative creative partner · shared production.

| Attribute | Definition |
|-----------|------------|
| **Entry** | Partner Studio™ → shared workspace |
| **Visibility** | Shared boards · transit objects · scoped departments |
| **Hidden** | Unrelated projects · financial data · founder boardroom |
| **Collaboration** | Co-presence at boards · handoff stations · dual attribution |
| **Duration** | Project-scoped · recurring access |
| **Narrative** | Professional · collaborative · evidence-rich |

### Type 3 — Contractor / Specialist

**Relationship:** Executes specific craft · temporary department access.

| Attribute | Definition |
|-----------|------------|
| **Entry** | Department guest desk (Photography · Motion · etc.) |
| **Visibility** | Assigned project artifacts · relevant references |
| **Hidden** | Full campus · strategy · other projects |
| **Collaboration** | Work at guest desk · deliver to transit station |
| **Duration** | Task-scoped · time-limited token |
| **Narrative** | Craft-focused · workshop atmosphere |

### Type 4 — Investor / Stakeholder

**Relationship:** Evaluates company trajectory · executive visibility.

| Attribute | Definition |
|-----------|------------|
| **Entry** | Executive corridor → Founder Boardroom™ or Mission Control™ |
| **Visibility** | Milestones · Hall of Legacy™ · growth exhibits |
| **Hidden** | Creative process chaos · rejection archives · WIP |
| **Collaboration** | Observation · scheduled briefing · Q&A at boardroom |
| **Duration** | Event-scoped |
| **Narrative** | Institutional · confident · trajectory-focused |

### Type 5 — Press / Media

**Relationship:** Public narrative · controlled reveal.

| Attribute | Definition |
|-----------|------------|
| **Entry** | Press Room™ |
| **Visibility** | Approved public artifacts · press kit gallery |
| **Hidden** | Everything else |
| **Collaboration** | Guided tour · photography-allowed zones |
| **Duration** | Event-scoped |
| **Narrative** | Editorial · brand-controlled |

## Visitor Arrival Sequence

```
1. INVITATION — Founder issues Visitor Pass™ (scoped token)
        ↓
2. THRESHOLD — Visitor Atrium™ (not founder lobby)
        ↓
3. ORIENTATION — Guest Orb explains path · rules · duration
        ↓
4. GUIDED PATH — Curated transitions (no free campus roam by default)
        ↓
5. COLLABORATION — Presentation · review · co-creation (type-dependent)
        ↓
6. DEPARTURE — Guest book signature · session chronicle
        ↓
7. FOUNDER DEBRIEF — Orb summarizes visitor session · annotations preserved
```

Visitors never experience the full founder journey. They experience a **designed guest narrative**.

## Visitor Evidence Model

Visitors leave **physical evidence** of their session:

| Evidence | Purpose |
|----------|---------|
| Guest book entry | Chronicle · who visited when |
| Annotation layer | Visitor feedback pinned to objects (scoped) |
| Approval gesture | Client sign-off recorded at Review Theater |
| Presentation remnants | Boards left in presentation configuration |
| Photo capture zones | Press-allowed documentation points |

Visitor evidence integrates into **organizational memory** — not a separate system.

## Visitor Presentation Modes

The environment adapts for visitor context:

| Mode | Environmental shift |
|------|---------------------|
| **Client reveal** | Approved work foregrounded · rejection hidden · lighting warm |
| **Agency collab** | Shared boards active · both attributions visible |
| **Investor briefing** | Milestone exhibits illuminated · tactical displays |
| **Press walkthrough** | Brand-controlled path · photography markers |

Presentation modes are **World State™ variants** — not separate builds.

---

## Visitor Security Principles

1. **Scope by token** — every visitor pass defines exact path · duration · visibility
2. **No genome access** — visitors never see Company Genome™ internals
3. **No taste access** — Founder Taste Genome™ is founder-private
4. **No cross-project** — visitors see only invited project artifacts
5. **Chronicle everything** — all visitor sessions recorded in organizational memory
6. **Revocable instantly** — founder can end visitor session · path closes

## Visitor Collaboration Primitives

| Primitive | Description |
|-----------|-------------|
| **Guided walk** | Orb leads visitor along curated path |
| **Seated review** | Visitor in Review Theater · presented work |
| **Pointer approve** | Visitor indicates approval on specific object |
| **Scoped annotate** | Visitor sticky note on permitted surface |
| **Co-board** | Agency partner manipulates shared board |
| **Guest desk** | Contractor produces work at assigned station |
| **Observation only** | Investor watches · no manipulation |

---

## Anti-Patterns

| Anti-pattern | Violation |
|--------------|-----------|
| Full campus access for all visitors | Security · narrative failure |
| PDF export as primary deliverable | Environment should be presentation |
| Visitor sees rejection archive | Breaks client narrative |
| Anonymous visitor link | No identity · no chronicle |
| Visitor chat panel | Not spatial |
| Separate "client portal" product | Should be same world · scoped path |

## Closing

When a client asks *"Can I see the work?"* — the answer is not a link.

The answer is: *"Arrive at our headquarters. We'll walk you through."*

That is the Visitor Interaction Model.
