# Founder Taste Engine™ — Master Specification

**"The AI That Learns How You Think"**

---

## Core Law

**Learn WHY — not just WHAT.**

Every founder decision is a taste signal. Studio OS must analyze the reasoning behind choices, not merely record outcomes.

---

| Property | Value |

| **Name** | Founder Taste Engine™ |

| **Scope** | Founder-scoped · cross-company · permanent |
| **Output** | Founder Taste Genome™ |

```
┌─────────────────────────────────────────────────────────────────┐
│                    FOUNDER DECISIONS                             │
│  approvals · rejections · branches · feedback · selections     │
├─────────────────────────────────────────────────────────────────┤
│                    TASTE LEARNING™                             │
│  Signal capture · WHY analysis · pattern extraction            │
├─────────────────────────────────────────────────────────────────┤
│                 FOUNDER TASTE GENOME™                          │
│  Visual · architectural · motion · brand · decision patterns     │
├─────────────────────────────────────────────────────────────────┤
│                    PREDICTIVE DESIGN™                          │
│  Concept prioritization · weak concept elimination · weighting   │
├─────────────────────────────────────────────────────────────────┤
│              PLATFORM CONSUMPTION LAYER                        │
│  Generation · Braintrust · Marketplace · Orb · Studio World™    │
└─────────────────────────────────────────────────────────────────┘
```

**No new generation engine.** Taste Engine **influences** existing engines.

---

## Taste Signal Pipeline

```
Founder decision event
        ↓
1. CAPTURE — what was decided (approve/reject/select/branch/feedback)
        ↓
2. CONTEXT — attach genomes · concept metadata · comparison set
        ↓
3. ANALYZE — extract taste dimensions (WHY not just WHAT)
        ↓
4. WEIGHT — confidence based on consistency · recency · stakes
        ↓
5. UPDATE — Founder Taste Genome™ mutation
        ↓
6. PROPAGATE — Predictive Design™ · Canon™ · Orb observations
```

Founder selects Concept A · B · C — or requests more.

Permanent **Founder Taste Genome™** accumulates across all companies.

Over time, Studio OS **prioritizes concepts matching taste** and **eliminates concepts conflicting with taste** — with transparency.

## Relationship to Relationship Memory™

| System | Learns | Example |
|--------|--------|---------|
| **Relationship Memory™** | How founder **works** | "Prefers visual review before implementation" |
| **Founder Taste Engine™** | How founder **creates** | "Consistently prefers single architectural focal points" |

Both are founder-scoped. Both learn through observation. **Complementary — not duplicate.**

Relationship Memory™ = operational familiarity.  
Founder Taste Engine™ = creative identity.

---

## Relationship to Organization Genome™

| Genome | Scope | Changes when |
|--------|-------|--------------|
| **Organization Genome™** | One company | Company evolves · Blueprint updates |
| **Founder Taste Genome™** | One founder | Every creative decision across all companies |

Taste Engine **informs** Company Genome brand direction.  
Company Genome does **not** replace Taste Genome.

## Confidence Model

Taste patterns require evidence:

| Confidence | Requirement |
|------------|-------------|
| **Hypothesis** | 1–2 signals · Orb may mention tentatively |
| **Emerging** | 3–5 consistent signals |
| **Established** | 6+ signals · cross-project consistency |
| **Core identity** | 10+ signals · multi-year · cross-company |

Founder may **confirm · reject · refine** any observation — overrides automatic learning.

---

## Privacy & Control

| Control | Behavior |
|---------|----------|
| **Confirm observation** | Boost confidence · lock pattern |
| **Reject observation** | Suppress pattern · negative weight |
| **Refine observation** | Adjust dimension · recalibrate |
| **Export taste profile** | Founder owns creative identity data |
| **Delete taste history** | Reset genome · start fresh |
| **Per-company taste overlay** | Optional — company-specific adjustments without losing founder core |

---

## Anti-Patterns

| Anti-pattern | Why forbidden |
|--------------|---------------|
| Remember clicks without WHY analysis | Shallow personalization |
| Manual taste preference forms | Founder teaches through decisions |
| Taste locked to one company | Violates Taste Transfer™ |
| Delete rejected concepts silently | Lose Alternate Branch™ value |
| Single concept generation | No learning signal · no choice |
| Taste overrides founder without transparency | Trust destruction |
| Confuse taste with demographics | Taste from **decisions** only |
