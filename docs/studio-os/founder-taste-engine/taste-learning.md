# Taste Learning™

**Analyze WHY — not just WHAT**

---

## Purpose

Define how Founder Taste Engine™ automatically analyzes every founder decision to extract **creative instinct patterns**.

The founder never fills a taste survey. **Decisions reveal taste.**

---

## Core Law

The important part is **not** which concept was selected.

The important part is **WHY**.

---

## Signal Types

| Event | Captured data | Taste extraction |
|-------|---------------|------------------|
| **Approve™** | Approved artifact + context | Positive weight on traits |
| **Reject™** | Rejected artifact + context | Negative weight on traits |
| **Regenerate™** | Same intent · new attempt | Correction vector |
| **Branch™** | Parallel preserved version | Nuance · non-binary preference |
| **Compare™** | A vs B active view | Relative preference strength |
| **Select vision** | Concept A/B/C choice | Vision-level instinct |
| **Director Feedback™** | Natural language | Explicit taste vocabulary |
| **Trust My Instinct™** | Skip Braintrust | Confidence in own taste |
| **Save Alternate Branch™** | Rejected → preserved | Exploratory dimension |
| **Conversation** | Onboarding · Orb dialogue | Stated values |

## Automatic Pattern Detection

Studio OS analyzes decisions over time:

| Detected pattern | Example evidence |
|------------------|------------------|
| Minimal interfaces | Rejected cluttered dashboards · approved clean layouts |
| Large hero objects | Selected concepts with dominant focal points |
| Bright environments | Consistent selection of high-key lighting |
| Architectural composition | Preferred strong structural lines |
| Luxury materials | Marble · acrylic · chrome selections |
| Editorial typography | Rejected system fonts · approved serif headlines |
| Cinematic transitions | Preferred film-style movement |
| Interactive storytelling | Chose experiential nav over traditional menus |
| Studio World™ navigation | Rejected page-swap patterns |
| Game-inspired navigation | Selected spatial exploration concepts |

**Not because they said so. Because their decisions reveal it.**

---

## Learning Algorithm (Conceptual)

```
For each decision event:
  1. Extract trait vector from selected vs rejected concepts
     (materials · scale · density · warmth · motion · typography…)
  2. Weight by decision stakes (vision lock > refinement > minor tweak)
  3. Weight by recency (recent decisions matter more — with decay)
  4. Weight by consistency (repeated pattern > one-off)
  5. Update Taste Genome™ dimensions
  6. Generate observation if confidence threshold crossed
  7. Feed Predictive Design™ model
```

## WHY Analysis Examples

### Example 1 — Concept Selection

Founder selects Concept B (cinematic glass precision) over A (warm editorial) and C (bold urban).

| Extracted WHY | Taste dimension update |
|---------------|------------------------|
| Glass over marble | Material: glass +0.3 · marble −0.1 |
| Cool precision over warmth | Temperature: cool +0.2 |
| Story Table™ centered vs Mood Wall™ hero | Hero preference: balanced −0.2 · focal +0.1 |
| Less decorative density | Clutter tolerance: low +0.3 |

### Example 2 — Director Feedback™

> "Warmer and more cinematic with less marble."

| Parsed intent | Update |
|---------------|--------|
| Warmer | Temperature +0.4 (explicit) |
| More cinematic | Motion/mood +0.3 |
| Less marble | Material marble −0.5 (explicit) |

### Example 3 — Rejection Pattern

Founder rejects 4 of 5 concepts with traditional dashboard layouts.

| Pattern | Update |
|---------|--------|
| Anti-SaaS dashboard | Interface taste: experiential +0.5 · dashboard −0.6 |
| Confidence | Established after 4 signals |

## Comparison Learning

When founder views Compare™ between A and B:

| Signal | Strength |
|--------|----------|
| Immediate selection | Strong preference |
| Long dwell on B · then select A | A wins · B traits partially positive |
| Request blend | Non-binary taste · hybrid dimension |
| Reject both · request more | Current set missed taste · widen exploration |

---

## Negative Learning

Rejections teach as much as approvals:

| Rejection type | Learning |
|----------------|----------|
| "Too corporate" | Corporate aesthetic −weight |
| "Too cluttered" | Visual density −weight |
| "Feels cheap" | Material tier minimum raised |
| "Too safe" | Creative risk tolerance +weight |
| Braintrust agrees with rejection | Validates taste pattern |

---

## Founder Override

Automatic learning is **probabilistic**. Founder has final authority on identity:

| Founder action | Effect |
|----------------|--------|
| Confirm Orb observation | Lock pattern · max confidence |
| Reject observation | Suppress · apply negative correction |
| Refine observation | Adjust dimension boundaries |
| "That's not me" | Rollback recent mutations on that dimension |

---

## Anti-Patterns

| Anti-pattern | Why |
|--------------|-----|
| Learn only from approvals | Rejections are half the signal |
| Single-decision conclusions | Require consistency threshold |
| Ignore comparison context | Relative preference matters |
| Learn from non-founder users | Taste Genome is founder-scoped |
| Opaque learning | Orb must be able to explain |
