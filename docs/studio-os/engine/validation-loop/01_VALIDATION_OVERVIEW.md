# 01 — Validation Overview

**Engine Module:** `studio.validation-loop.v1.overview`

---

## What Is Studio Validation Loop™?

Studio Validation Loop™ is the **official quality engine** governing every department, expansion, project, asset, workflow, AI recommendation, and Marketplace package across Studio OS.

> Not QA. QA checks if something works. Validation determines whether something deserves to exist.

It is the **final creative authority** before anything is approved for Headquarters installation.

---

## Purpose

> Ensure nothing generated by Studio OS moves directly from generation to implementation without passing technical quality, creative quality, experiential quality, brand alignment, emotional impact, accessibility, and long-term maintainability review.

The Validation Loop exists because:

1. **Generation is cheap; judgment is scarce** — AI can produce infinite departments; only some deserve to exist
2. **Brand integrity requires gates** — Company Genome must be unmistakable in every output
3. **Place-not-page is enforceable** — creative and experience review catch SaaS drift
4. **Founder trust compounds** — every approval/rejection teaches the system
5. **Marketplace requires trust signals** — certification communicates quality to buyers
6. **Evolution is continuous** — validation does not end at launch

## Relationship Map

### Studio Department SDK™

| SDK Provides | Validation Enforces |
|--------------|---------------------|
| Anatomy law (01) | Department Review |
| Anti-SaaS patterns (07) | Creative Review |
| QA Checklist (17) | Self Review stage |
| Interaction verbs (04) | Department Review — interaction audit |
| Golden Department principles | Experience Review benchmark |

### Studio Department Generator™

| Relationship | Detail |
|--------------|--------|
| Generator QA (16) | Maps to **Self Review** — not sufficient alone |
| Generator output | Submitted to Validation before Compiler handoff **or** after Compiler cook (configurable per artifact type) |
| Revision Engine | Uses Generator regeneration scopes (14) |

**Recommended gate:** Validate after **Compiler cook + Runtime preview** — founders review living place, not blueprints.

### Studio Asset Compiler™

| Relationship | Detail |
|--------------|--------|
| Compiler QA (12) | Technical self-review — schema, dependencies, asset integrity |
| Validation adds | Creative, experiential, Genome layers on cooked assets |

### Studio Department Runtime™

| Relationship | Detail |
|--------------|--------|
| Runtime QA (20) | Readiness check within Self Review |
| Install block | Runtime refuses HQ install without `validationApprovalToken` |
| Preview mode | Runtime assembles preview sessions for Experience Review |

### Company Genome™

Genome Validation (05) is **non-negotiable** for all department packages. Fail if output could belong to another company.

### Creative Direction Studio™

Living creative authority — Braintrust Creative Director references active Creative Direction before critiquing production departments.

### Headquarters Marketplace™

No listing publishes without Marketplace Certification (13). Certification badges communicate trust.
