# Frontal Slayer Admin Alignment Protocol

**Scope:** Frontal Slayer **Admin Dashboard** only (`/admin/dashboard`, `/admin/clients`, `/admin/marketing`, `/admin/meetings`, etc.).

**Not in scope:** Customer-facing pages (see [design-dna-canon/](./design-dna-canon/)) · Studio OS Headquarters modules (see [executive-information-architecture.md](../studio-os/executive-information-architecture.md)).

This is **not** a redesign initiative. It is a **controlled alignment** initiative.

---

## Core principle

Existing approved pages are **protected**.

Do **not** redesign, modernize, standardize, normalize, or "improve" any page unless the founder **explicitly identifies** it.

**Assume every existing admin page is finalized unless told otherwise.**

---

## Explicit authorization

Only modify pages that are **specifically requested**.

Examples:

- "Align the Orders page."
- "Update the Customer Profile."
- "Improve the Membership page."

**If a page is not named, do not touch it.**

---

## Section-level control

Even when a page is approved for alignment, do **not** redesign the entire page.

Only modify the **specific sections or features** identified.

Examples:

- "Update only the hero section."
- "Only redesign the analytics cards."
- "Only improve the activity feed."
- "Only reorganize the appointment section."

Everything else on that page remains **unchanged**.

---

## Canon reference pages

When the founder identifies a page they love, treat it as a **Canon Reference**.

Canon Reference pages should **never** be altered.

Use them as inspiration for future alignment work. Study:

- Information hierarchy
- Spacing rhythm
- Visual balance
- Component usage
- Luxury feel
- Organization
- Interaction style

Do **not** copy pixel-for-pixel. **Learn** from them.

---

## Alignment objective

The objective is **visual coherence** — not visual uniformity.

Future aligned pages should feel like they belong in the same admin experience while preserving each page's unique purpose.

---

## Before making changes

For every requested alignment:

1. **Identify the page.**
2. **Identify the exact sections requested.**
3. **List what will remain untouched.**
4. **Explain the proposed improvements.**

Wait for approval before implementing if scope is unclear.

---

## Never assume

Never assume an element should change because another page does something differently.

Differences may be **intentional**.

If uncertain, **ask**.

---

## Preserve (unless explicitly requested)

- Custom spacing
- Custom typography
- Custom compositions
- Custom layouts
- Approved interactions
- Approved animations
- Approved visual hierarchy

---

## Success criteria

Every newly aligned page should feel as though it has **always belonged** inside the Frontal Slayer Admin Dashboard.

The goal is **not** to make every page identical.

Every alignment should be **intentional**, **surgical**, and **founder-approved**.

**Nothing changes unless the founder asks for it.**
