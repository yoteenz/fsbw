## Mission

Define the philosophy that every capability inside Studio OS exists as a **real place** inside Studio World.

Users should never feel like they are navigating software. They should feel like they are **operating a living company**.

This philosophy becomes the **permanent lens** through which every future feature, sprint, module, and marketing message is evaluated — before design, before engineering, before launch.

| We build | We do not build |
|----------|-----------------|
| Headquarters | Dashboards |
| Departments | Feature tabs |
| Meetings | Prompt boxes |
| Events | Workflows |
| Places | Pages |
| Presence | Productivity metrics as primary UX |

## The Core Belief

**Software disappears.**

| Old paradigm | Spatial paradigm |
|--------------|------------------|
| Productivity | **Presence** |
| Pages | **Places** |
| Features | **Departments** |
| Workflows | **Experiences** |
| Prompting | **Meetings** |
| Dashboards | **Worlds** |

The founder does not *use* Studio OS. The founder **inhabits** Studio World.

The interface is not a surface laid over data. The interface **is** the company — addressable, walkable, memorable, and alive.

## Design Constitution

Every capability has a home.  
Every home has a purpose.  
Every purpose belongs to a department.  
Every department belongs to Studio World.

**Nothing exists without spatial context.**

| Law | Requirement |
|-----|-------------|
| **No orphan pages** | Every route resolves to a building, wing, floor, or room |
| **No floating features** | Every control belongs to a department with visible evidence of work |
| **No isolated utilities** | Settings, analytics, notifications — all have addresses |
| **Everything lives somewhere** | If it cannot be placed on the map, it is not ready to ship |

### Constitutional hierarchy

```
Capability  →  Home (room/set)  →  Department  →  District  →  Studio World
```

A feature without a home is not a feature. It is **unfinished architecture**.

## The Studio Ecosystem

The Studio ecosystem is a **single living organization** with a clear vertical hierarchy. Each layer has a distinct role. None may be collapsed into generic "software."

```
Studio
The company.

    ↓

Studio OS
The operating system.

    ↓

Studio World
The headquarters and immersive universe.

    ↓

Genesis
The intelligence that keeps Studio World alive.

    ↓

Creative Studios
Production.

    ↓

Studio Institute
Learning.

    ↓

Experience Lab
Simulation and testing.

    ↓

World Compiler
World generation.
```

### Layer definitions

| Layer | Role | Spatial identity |
|-------|------|------------------|
| **Studio** | The company — brand, mission, people, revenue, legacy | The organization as a whole |
| **Studio OS** | Operating system — modules, governance, runtime, permissions | Infrastructure of the headquarters |
| **Studio World** | Headquarters and immersive universe — where work is felt | The campus · the city · the place |
| **Genesis** | Consciousness of Studio World — coordination, memory, attention | Not a page — ambient intelligence throughout |
| **Creative Studios** | Production — creative direction, review, assembly, output | Production floors · review theaters · studios |
| **Studio Institute** | Learning — curriculum, certification, mastery paths | Academy wings · lecture halls · libraries |
| **Experience Lab** | Simulation and testing — safe rehearsal before live deployment | Lab alcoves · sandboxes · validation chambers |
| **World Compiler** | World generation — headquarters compilation, scene assembly | Foundry · compile floor · generation bay |

**Law:** Lower layers serve upper layers. No layer may present itself as "just another app inside the OS." Each layer is a **place** with organizational meaning.

## The "Where Does It Live?" Rule

Every new feature proposal must answer **one question** before implementation:

### Where does this live?

If the answer is unclear, the feature is **not approved** for build.

| Capability | Lives in |
|------------|----------|
| Analytics | **Executive Intelligence Center** |
| Settings | **Operations Office** |
| Notifications | **Communications Center** |
| Creative Review | **Creative Studios** |
| Education | **Studio Institute** |
| Rendering | **World Compiler** |
| AI coordination | **Genesis** (ambient — not a destination page) |
| Brand strategy | **Creative Direction Studio™** |
| Hiring | **People & Talent wing** |
| Financial review | **Financial Operations** |
| Documentation | **Knowledge Registry / Institute archives** |
| Experiments | **Experience Lab** |
| Company onboarding | **Grand Atrium™ / Inauguration sequence** |

### Placement workflow

1. **Name the capability** in organizational terms (not SaaS terms).
2. **Assign a department** that owns it operationally.
3. **Assign a physical place** — building · wing · room · set.
4. **Define Genesis interaction** — how intelligence surfaces it (briefing, meeting, ambient signal).
5. **Verify on the map** — Atlas / World Graph must contain the node before ship.

**Forbidden answer:** "It lives in a new tab" or "It lives in the sidebar." Those are implementation leaks, not homes.

## The Genesis Principle

Genesis is **not** an assistant.  
Genesis is **not** a chatbot.  
Genesis is **not** a page.

**Genesis is the consciousness of Studio World.**

Genesis knows:

- every employee
- every department
- every meeting
- every compile
- every business
- every project
- every render
- every founder

### Division of labor

| Entity | Role |
|--------|------|
| **Genesis** | Coordinates · remembers · schedules · briefs · connects |
| **Departments** | Execute · produce · review · teach · compile |
| **Founder** | Arrives · decides · directs · leads |

Genesis does not replace departments. Genesis **orchestrates** them.

Genesis does not wait in a chat window. Genesis **meets** the founder in context — Morning Briefing™, board rooms, Orb approach, ambient signals in corridors.

**Law:** Any UI that presents Genesis as a floating chat panel violates this constitution unless explicitly scoped as a **meeting room** or **executive session** inside Studio World.

## The User Experience Principle

The founder should **never** feel like they are:

- opening pages
- clicking menus
- using software

The founder **should** feel like they are:

- **arriving**
- **walking**
- **reviewing**
- **meeting**
- **operating**
- **directing**
- **leading**

### Experience verbs (approved)

| Verb | Meaning |
|------|---------|
| Arrive | Enter headquarters — continuity from last session visible |
| Walk | Move between departments — corridors, not route changes |
| Review | Stand before work already prepared — not blank generation |
| Meet | Attend scheduled or summoned sessions — specialists present |
| Operate | Pull levers inside a department — room is the interface |
| Direct | Issue decisions that become memory — not save buttons |
| Lead | Stand at executive altitude — observation decks, not admin grids |

### Experience verbs (forbidden as primary UX)

Open · Click · Navigate · Configure · Generate · Prompt · Tab · Scroll-through-dashboard

These may exist as **implementation details** hidden inside places. They must never be the **founder's mental model**.

## The Language Constitution

Avoid software language whenever possible.

Language shapes belief. If we speak like SaaS, we build like SaaS. If we speak like a company, we build like a company.

| Avoid | Use instead |
|-------|-------------|
| Dashboard | **Headquarters** · **Executive Intelligence Center** |
| Workspace | **Department** · **Studio** · **Room** |
| Settings | **Operations Office** |
| Analytics | **Executive Intelligence Center** |
| Notifications | **Communications Center** |
| AI Assistant | **Genesis** |
| Tutorials | **Studio Institute** |
| Feature | **Capability** · **Department function** |
| User | **Founder** · **Executive** · **Team member** |
| Admin panel | **Operations wing** |
| Module | **Department** · **System within headquarters** |
| Export | **Archive** · **Artifact delivery** |
| Upload | **Intake** · **Briefing table** |
| Chat | **Meeting** · **Session** |
| Prompt | **Brief** · **Agenda** · **Meeting charter** |

### Naming law

New surfaces ship with **organizational names first**. Technical route names and internal module IDs are secondary. Marketing, navigation, and founder-facing copy must use the Language Constitution.

## The Presence Principle

**The software should disappear. The company should become tangible.**

Users should eventually think:

- *"I'm heading to Creative Review."*
- *"Genesis scheduled my board meeting."*
- *"The World Compiler is generating my headquarters."*
- *"The design team finished three concepts."*
- *"I'll learn that inside the Institute."*

Users should **never** think:

- *"I opened Settings."*
- *"I clicked Analytics."*
- *"I used AI."*

### Presence signals

| Signal | Description |
|--------|-------------|
| **Worked surfaces** | Evidence of labor before founder arrival |
| **Ambient life** | Departments active without founder input |
| **Scheduled continuity** | Meetings and compiles exist on a timeline |
| **Spatial memory** | Founder returns to the same room state |
| **Named destinations** | Colleagues could say "meet me in Creative Studios" |

### Anti-presence patterns

- Blank states awaiting founder prompt
- Feature grids without architectural context
- Chat-as-home-screen
- Settings buried in avatar menus with no Operations Office identity
- "Generate" as the first action with no prepared context

## The Experience Principle

Every workflow should feel like an **event** — something that **happens somewhere**, at a time, with people (human or AI), leaving memory behind.

| Event type | Place |
|------------|-------|
| Creative Reviews | Creative Studios — review theater |
| Board Meetings | Executive Boardroom |
| Brand Strategy Sessions | Creative Direction Studio™ |
| Packaging Reviews | Production floor · packaging bay |
| Hiring Interviews | People & Talent wing |
| Motion Reviews | Motion studio |
| Institute Lessons | Studio Institute — classroom |
| Department Standups | Department floor · morning circle |
| Founder Briefings | Grand Atrium™ · Morning Briefing™ |
| Compile runs | World Compiler — foundry floor |
| Lab simulations | Experience Lab |

**Law:** If a workflow can be completed without the founder sensing **where** and **when** it occurred, the workflow lacks experiential architecture.

Events produce **artifacts** (decisions, outputs, lessons, memory). Artifacts remain visible in the place where the event occurred.

## The Design Review Checklist

Before any feature ships, require affirmative answers to **all** questions:

| # | Question | Required answer |
|---|----------|-----------------|
| 1 | **Where does it live?** | Named building · wing · room · set |
| 2 | **Who owns it?** | Department or executive role |
| 3 | **What department operates it?** | Organizational unit — not "platform team" |
| 4 | **How does Genesis interact with it?** | Briefing · meeting · ambient · schedule — not orphan chat |
| 5 | **What physical place represents it?** | Describable environment with evidence of work |
| 6 | **Does it reinforce immersion?** | Yes |
| 7 | **Would it feel believable inside Studio World?** | Yes |

**If any answer is "no" or "unclear" — revisit the design.** Do not ship and fix later.

### Review participants

- Product / architecture — placement and ownership
- Experience design — presence and language
- Engineering — route and module alignment with World Graph
- Documentation — canon and glossary update
