## Mission

Create a **permanent naming constitution**.

Studio should eventually become recognizable because **everything shares one coherent language** — not because one product went viral.

| Goal | Measure |
|------|---------|
| **Coherence** | New names feel pre-existing inside Studio World |
| **Recognition** | "This feels like Studio" without explanation |
| **Longevity** | Names survive ten years and global scale |
| **Expandability** | One name can grow beyond a single feature |

Every future name — product, place, system, AI role, department, technology, public identity — passes through this engine **before** canon adoption.

---

## The Core Philosophy

**Do not build products. Build a civilization.**

**Do not create features. Create places.**

**Do not invent names. Create a language.**

Every future name should feel like it **already existed** inside Studio World — discovered, not fabricated.

| Anti-pattern | Studio pattern |
|--------------|----------------|
| Feature label (`Analytics Pro`) | Organizational place (`Executive Intelligence Center`) |
| Trendy startup coinage (`Studly`, `GenieOS`) | Timeless institutional language (`Genesis`, `Institute`) |
| Capability lock-in (`StudioAIChat`) | Ecosystem identity that scales (`Genesis`) |
| Suffix clutter (`StudioAppOfficial`) | Premium restraint — suffix only when legally or strategically required |
| One-off marketing names | Tiered canon that compounds over decades |

The language is **part of the product**. Names are architecture, not decoration.

## Naming Constitution

These laws govern all Studio naming. No exception without founder constitutional amendment.

### Article I — Tier discipline

Every name belongs to exactly **one** naming tier (Company · World · System · Experience). Mixing tiers in a single string without documented compound rules is forbidden.

### Article II — Spatial alignment

Place and product names must align with [The Spatial Computing Philosophy™](./THE_SPATIAL_COMPUTING_PHILOSOPHY.md). If it cannot be placed in Studio World, it cannot be named in canon.

### Article III — No capability lock-in

Public and ecosystem identities must not encode a single feature (e.g. `StudioDashboard`, `StudioChatBot`). Names must survive product pivots.

### Article IV — Premium restraint

Avoid gratuitous suffixes: `official`, `app`, `hq`, `ai`, `pro`, `plus`, `beta`, `v2` in **public-facing brand strings** unless legally or strategically justified and documented.

### Article V — Trademark consciousness

Names are evaluated for distinctiveness and clearance **before** emotional attachment. Design what deserves to exist; then search availability.

### Article VI — Pronunciation & global scale

Names must be speakable on a boardroom call, a podcast, and an international stage. Avoid ambiguous spellings and unpronounceable abbreviations in Tier 1–3.

### Article VII — Canon registry

Adopted names enter the glossary ([AI_GLOSSARY.md](../docs/ai-collaboration/AI_GLOSSARY.md)) and documentation registry. Deprecated names retain redirect notes — never silent renames.

### Article VIII — ™ discipline

Trademark symbol (™) usage follows existing project convention: product/system names in documentation and UI labels where canon requires; not on every sentence in prose.

| Name | Tier | Role |

| **Creative Studios** | World (Tier 2) | Creation · production |

### Compound naming rules

| Pattern | Example | When to use |
|---------|---------|-------------|
| **Studio + [Institution]** | Studio Institute | Tier 2 worlds under company umbrella |

## The Four Naming Tiers

```
Tier 1 — Company        Studio
Tier 2 — Worlds         Studio World · Studio Institute · Creative Studios · …
Tier 3 — Systems        Genesis · World Compiler · Atlas · …
Tier 4 — Experiences    Board Meeting · Creative Review · Founder Briefing · …
```

### Tier 1 — Company

**One primary company identity:** **Studio**.

| Rule | Detail |
|------|--------|
| Scope | Legal entity, movement, civilization umbrella |
| Extensions | Rare — only for disambiguation in legal contexts |
| Social handle | Represents entire ecosystem — not one product (see Social Handle Methodology) |

### Tier 2 — Worlds

**Immersive destinations** — places founders inhabit.

| Canonical examples | Role |
|--------------------|------|
| **Studio World** | Headquarters · immersive universe |
| **Studio Institute** | Learning · certification · mastery |
| **Creative Studios** | Production · creative direction · review |
| **Studio Forge** | Manufacturing · asset production (reserved) |
| **Studio Labs** | Experimentation · Experience Lab adjacency (reserved) |

**Naming pattern:** `Studio + [Civilization noun]` or `[Evocative place noun]` that passes the Studio Test.

Worlds feel like **districts or campuses** — not feature bundles.

### Tier 3 — Systems

**Infrastructure and intelligence** — what keeps the world alive.

| Canonical examples | Role |
|--------------------|------|
| **Genesis** | Organizational consciousness |
| **World Compiler** | Headquarters and scene generation |
| **Context Protocol** / **AI Context Protocol™** | Institutional memory transfer |
| **Knowledge Graph** | Relational intelligence |
| **Learning DNA** | Institute personalization engine |
| **Atlas** | Geographic / navigational intelligence |

**Naming pattern:** `[Evocative proper noun]` or `[Function + Engine/Protocol/Graph]` — prefer timeless nouns over version numbers in the brand string.

Systems may use technical subtitles in docs (`manifest v3`) but **public name** stays stable.

### Tier 4 — Experiences

**Events and rituals** — what happens somewhere.

| Canonical examples | Role |
|--------------------|------|
| **Board Meeting** | Executive decision ritual |
| **Creative Review** | Production critique session |
| **Founder Briefing** | Morning intelligence ritual |
| **Innovation Summit** | Strategic exploration event |
| **Design Council** | Cross-functional design governance |

**Naming pattern:** `[Role or function] + [Event noun]` — must complete the sentence *"I'm heading to ______."*

Experiences are **never** named like software actions (`Click Export`, `Open Settings Modal`).

## Product Naming Framework

**Products** are founder-facing capabilities with persistent identity. They usually map to Tier 2 Worlds or Tier 3 Systems.

### Decision tree

```
Is it primarily a place the founder enters?
  YES → Tier 2 World naming (Place Naming Framework)
  NO → Is it infrastructure / intelligence?
    YES → Tier 3 System naming (System Naming Framework)
    NO → Is it a ritual or session?
      YES → Tier 4 Experience naming
      NO → Revisit spatial placement — may not be name-ready
```

### Product naming rules

| Rule | Requirement |
|------|-------------|
| **One primary name** | One canon string; aliases deprecated explicitly |
| **No version in brand** | `World Compiler` not `World Compiler 2.0` publicly |
| **Organizational nouns** | Prefer Institute, Studios, Forge, Atlas over Module, Tool, Widget |
| **Pair with tagline in docs** | Tagline explains; name evokes |
| **Avoid acronym-first** | `CDS` only after `Creative Direction Studio™` is established |

### Product name review checklist

- [ ] Tier assigned
- [ ] Spatial home documented ([Spatial Architecture Review](./SPATIAL_ARCHITECTURE_REVIEW.md))
- [ ] Passes Studio Test (§14)
- [ ] Scorecard ≥ 3.5 overall (§13)
- [ ] Glossary entry drafted

## Place Naming Framework

**Places** are spatial addresses inside Studio World — buildings, wings, floors, rooms, districts.

Aligns with [Language Constitution](./THE_SPATIAL_COMPUTING_PHILOSOPHY.md#the-language-constitution) — replace software words with organizational words.

### Place naming patterns

| Type | Pattern | Examples |
|------|---------|----------|
| **District** | `[Evocative geography]` | Grand Atrium™, Innovation Quarter |
| **Building** | `[Function] + [Architectural noun]` | Executive Headquarters, Production Hall |
| **Wing** | `[Department] + Wing` | Operations Wing, Reflection Wing |
| **Room** | `[Experience or function] + [Room type]` | Boardroom, Review Theater, Compile Foundry |
| **Set** | `[Production] + Set` | Weather Studio Set, Reference Scene |

### Place naming rules

| Rule | Detail |
|------|--------|
| **Addressable** | Founder can say "meet me in the Boardroom" |
| **No generic "Room 404"** | Names imply purpose |
| **Operations Office** not **Settings** | Language constitution |
| **Executive Intelligence Center** not **Analytics Dashboard** | Language constitution |
| **Communications Center** not **Notifications** | Language constitution |

### Place vs product

| Place | Product |
|-------|---------|
| Address inside Studio World | May span multiple places |
| "Where" | "What capability" |
| Tier 4 experiences happen in places | Tier 2/3 products contain places |

Every Tier 2 World contains named places. Every Tier 3 System that is founder-visible has a **physical representation** (see Spatial Architecture Review).

## AI Naming Framework

**AI** in Studio is not a product category — it is **organizational intelligence** distributed through Genesis, Studio AI™, and executive roles.

### Hierarchy

```
Genesis          → consciousness of Studio World (Tier 3 — never "the AI")
Studio AI™       → persistent intelligence layer (Tier 3 system brand)
Executive roles  → Creative Director, Chief Architect, Professors… (Tier 4 adjacency)
Foundation models → NOT branded as Studio products (replaceable engines)
```

### AI naming rules

| Do | Don't |
|----|-------|
| **Genesis** | `Studio AI Chat`, `AI Assistant`, `Copilot` |
| **Creative Director** (role) | `GPT Creative Mode` |
| **Professor Atlas** (persona) | `Atlas Bot v2` |
| **Reasoning Engine** (abstract) | `Claude Integration` as product name |

### Genesis naming law

**Genesis** is a proper noun — singular, timeless, without `Studio` prefix in primary copy.

| Context | Approved |
|---------|----------|
| Primary | "Genesis scheduled your board meeting." |
| Secondary disambiguation | "Genesis (Studio World intelligence)" in legal/docs only |
| Forbidden | "Use Genesis AI to chat", "Genesis Assistant page" |

### Role vs model

| Layer | Named | Example |
|-------|-------|---------|
| Persistent persona | Yes | Professor Motion |
| Foundation model | No | "powered by [engine]" in technical docs only |
| Session | No | Never brand the chat session |

New AI roles use **executive or institutional titles** — not cute bot names.

## System Naming Framework

**Systems** are Tier 3 — engines, protocols, registries, compilers, graphs.

### System naming patterns

| Pattern | When | Examples |
|---------|------|----------|
| **Proper noun (mythic / cosmic)** | Consciousness, origin, intelligence | Genesis |
| **[Noun] + Engine** | Processing pipelines | World Compiler, Design Token Engine |
| **[Noun] + Protocol** | Standards, transfer formats | AI Context Protocol |
| **[Noun] + Graph / Registry / Atlas** | Data intelligence | Knowledge Graph, System Registry, Atlas |
| **[Noun] + DNA** | Identity encoding | Learning DNA, Company Genome |

### System naming rules

| Rule | Detail |
|------|--------|
| **Stable public string** | Internal codenames (M125, ARTICLE-K22) stay internal |
| **No vendor names** | Fal, OpenAI, Supabase — integration docs only |
| **Engine > Tool** | Implies ongoing institutional capability |
| **Protocol > Format** | Implies ecosystem standard |

### Deprecation

When systems merge, publish **supersedes** note in AI_CHANGELOG. Old names redirect in docs for minimum one release cycle.

## Social Handle Philosophy

The **social handle** is not required to exactly match any single product name.

The handle represents the **Studio ecosystem** — the civilization, not one capability.

### Handle qualities

| Quality | Requirement |
|---------|-------------|
| **Memorable** | Short enough to say aloud; distinct in a feed |
| **Premium** | No gimmick spelling (`Studi0`, `Gen3sis`) |
| **Timeless** | Survives product line changes |
| **Scalable** | Works when Studio ships ten more worlds |
| **Non-locking** | Does not encode one feature (e.g. `studioworldbuilder`) |
| **Restrained** | No gratuitous `official`, `app`, `hq`, `ai` unless strategic |

The handle should become **synonymous with the brand** — like `@apple` is Apple, not "iPhone company."

### Handle vs product name

| Product name | Handle |
|--------------|--------|
| May be descriptive (`Studio Institute`) | Should be **evocative and ecosystem-wide** |
| Can multiply (many worlds) | Should remain **one primary identity** |
| Uses Studio vocabulary | May omit "Studio" if stronger alone |

**This sprint does not select handles.** It defines how future handle sprints run.

## Social Handle Methodology

**The Social Handle Engine** — repeatable process for generating and evaluating candidates.

**Do not** simply append words to "Studio." Generate identities that feel like:

| Direction | Feels like | Strategic use |
|-----------|------------|---------------|
| **Movement** | Cultural momentum | Community, founder audience |
| **Destination** | Place you travel to | Immersive brand, events |
| **Institution** | Enduring authority | Enterprise, Institute adjacency |
| **Operating Company** | Serious infrastructure | B2B, platform |
| **World** | Universe expansion | Studio World marketing |
| **Headquarters** | Command center | Executive audience |
| **Civilization** | Long-horizon ambition | Vision narrative |
| **Origin** | Genesis adjacency | Creation myth, founding story |
| **Platform** | Technical credibility | Developer, partner |
| **Invitation** | Belonging | Onboarding, membership |

### Phase 1 — Generative expansion (no availability yet)

1. **Anchor** — confirm Tier 1 (`Studio`) and ecosystem nouns from Public Brand.
2. **Direction select** — pick 2–4 directions from table above (not all ten).
3. **Candidate burst** — generate **200 original candidates** across directions.
4. **De-genericize** — remove dictionary-only pairs (`studiohome`, `studioworld`), misspellings, trendy suffixes, year stamps.
5. **Group** — bucket survivors by naming philosophy direction.

### Phase 2 — Scoring (still no availability)

Apply [Evaluation Scorecard](#evaluation-scorecard) to each bucket's top candidates.

### Phase 3 — Availability (only after scoring)

Begin domain and handle searches **only** on candidates scoring ≥ 4.0 overall.

**Law:** Do not design around what is immediately available. Design around what **deserves to exist** — then negotiate acquisition, variation, or legal clearance.

### Phase 4 — Founder selection

Present **short list** (≤ 5) with scores, rationale, risks — not 200 raw names.

### Anti-patterns in handle generation

| Anti-pattern | Why |
|--------------|-----|
| `studio` + every product word | Locks ecosystem to one capability |
| `_official`, `real`, `the` prefixes | Low premium signal |
| Numbers and years | Dates the brand |
| Platform-specific hacks (`studio.world.only`) | Fragile |
| Copying competitor morphology | Breaks recognition |

## Availability Workflow

When creating future handles (after methodology Phase 1–2):

| Step | Action |
|------|--------|
| 1 | Generate **200 original candidates** |
| 2 | Remove generic variations |
| 3 | Group by naming philosophy direction |
| 4 | Score **uniqueness** (1–5) |
| 5 | Score **ecosystem fit** (1–5) |
| 6 | Score **long-term brand value** (1–5) |
| 7 | **Only then** begin availability searches (domain, social platforms, trademark preliminary) |

### Availability tiers

| Result | Action |
|--------|--------|
| Fully available + high score | Proceed to founder short list |
| Taken + exceptional score | Document acquisition / legal path |
| Available + low score | **Reject** — do not settle |
| Taken + low score | Discard without regret |

## Evaluation Scorecard

Every candidate name (product, place, system, experience, handle) receives scores **1–5** per dimension.

| Dimension | Measures |
|-----------|----------|
| **Memorability** | Easy to recall after one exposure |
| **Originality** | Distinct from competitors and generic SaaS |
| **Longevity** | Still credible in 10+ years |
| **Expandability** | Can grow beyond first use case |
| **Trademark potential** | Distinctive enough for protection path |
| **Global pronunciation** | Speakable internationally |
| **Visual identity** | Works in wordmark, Orb context, HQ signage |
| **Emotional resonance** | Evokes premium, presence, civilization |
| **Studio canon fit** | Aligns with tiers, spatial law, language constitution |

### Composite scores

| Score type | Formula | Gate |
|------------|---------|------|
| **Uniqueness** | (Originality + Trademark potential) / 2 | Handle Phase 3 |
| **Ecosystem fit** | (Studio canon fit + Expandability + Emotional resonance) / 3 | All adoptions |
| **Long-term brand value** | (Longevity + Memorability + Visual identity) / 3 | All adoptions |
| **Overall Brand Score** | Mean of all nine dimensions | **≥ 3.5** adopt · **≥ 4.0** flagship |

Flagship names (Tier 1–2 public launches) target **≥ 4.0**.

## The Studio Test

Every future name must answer **yes** to all five:

| # | Question |
|---|----------|
| 1 | **Could this still make sense ten years from now?** |
| 2 | **Could this represent more than one product?** |
| 3 | **Could this become a destination inside Studio World?** |
| 4 | **Could someone proudly say: "I'm heading to ______."** (or equivalent for systems: "Genesis handles ______.") |
| 5 | **Would it still feel premium if Studio became a global company?** |

**Any no** → revise or reject. Do not adopt "good enough" names that fail longevity or premium tests.

## The North Star

Studio should develop a **recognizable naming language** the way people recognize:

| Brand | What people recognize |
|-------|----------------------|
| **Apple** | Simplicity, singular nouns, no jargon |
| **Pixar** | Playful proper nouns, institutional craft |
| **Stripe** | Clean, verb-adjacent infrastructure |
| **Figma** | Short, tool-as-place feeling |
| **Nike** | Mythic, movement, one syllable power |

Studio's language should feel:

- **Institutional** — not startup-cute
- **Spatial** — places and events, not features
- **Timeless** — mythic and architectural nouns
- **Coherent** — Studio / Genesis / Institute / Compiler share a universe

**The language itself becomes part of the brand.** Explaining every name should become unnecessary — the vocabulary signals Studio.

## Adoption & Review Gate

### Before adopting any new canon name

1. Assign **naming tier**
2. Apply correct **framework** (product · place · AI · system)
3. Complete **Evaluation Scorecard**
4. Pass **Studio Test** (all five yes)
5. Confirm **spatial placement** ([Spatial Architecture Review](./SPATIAL_ARCHITECTURE_REVIEW.md))
6. Add entry to **AI_GLOSSARY.md** with tier and definition
7. Log decision in **AI_CHANGELOG.md** if public-facing

### Review artifact block

```markdown
**Brand Language alignment:** [Tier] · [Framework] · Overall Brand Score [x.x] · Studio Test PASS
```

Include in architecture reviews, sprint headers, and bible updates.

### Social handles

**Separate sprint.** Run [Social Handle Methodology](#social-handle-methodology) + [Availability Workflow](#availability-workflow). Do not generate final handles during product naming sprints.
